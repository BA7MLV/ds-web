# 性能与 SEO/GEO 优化结果

当前代码、自动化测试、最终生产静态验收与本地真实浏览器 A/B 验收已完成，未部署。
最终构建已纳入 iframe / 动画竞态、支持页机器导出、双语公开表述、未使用字体预载和 Tailwind 镜像扫描修正。
逐项证据与未完成门槛见 [验收清单](./验收清单.md)。
首页 head 所声明关键本地资源的 gzip 估算从 1,162,047 B 降至 120,684 B，减少 **89.61%**。
这证明初始资源成本下降，**不等同于加载时间已经提升 89.61%**；加载时间以同一时段的冷缓存浏览器 A/B 结果为准。

## 资源对比与统计口径

基线为修改前保存的 `/private/tmp/ds-web-perf.tgon5E/baseline`，
优化后为已包含本轮复审修正的最终构建 `docs/.vitepress/dist`。详细原始报告分别在：

- `perf/bench/baseline-audit.json`
- `perf/bench/audit.json`
- `perf/bench/benchmark-final.json`

| 指标 | 基线 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 首页 head 关键本地资源数 | 31 | 6 | −25 |
| 其中 JavaScript 入口 / 预载数 | 28 | 4 | −24 |
| 原始体积 | 3,828,559 B | 417,502 B | −89.10% |
| gzip 估算 | 1,162,047 B | 120,684 B | −89.61% |
| Brotli 估算 | 960,908 B | 104,836 B | −89.09% |
| 首页图表相关预载（含 KaTeX） | 24 | 0 | 首屏不再预载图表实现 |
| 首页 head 外部资源 | 2 | 0 | 移除 Google Fonts 阻塞样式与同步统计脚本 |

「关键本地资源」仅包含 HTML head 直接声明的脚本、modulepreload、样式与字体 preload；
两个 icon 单独列出，不纳入关键资源。压缩数值来自逐文件压缩估算，不包含 HTTP 头、
CSS 间接引用、运行时动态导入、iframe 后续资源或真实第三方时延。
轻量异步图表组件本身不等于 Mermaid 引擎，审计不会把它误报为图表实现预载。

原诊断还误计了已不被首页使用的 `home-*.png`。
当前功能区实际引用四张 `feature-*-dither.svg`，总计 116,128 B raw / 19,103 B gzip；
先前主动预热的后三张为 72,158 B raw / 12,099 B gzip。
这项调度优化保留，但它不是 MB 级瓶颈；主要字节收益来自移除首页图表依赖。
演示入口的直接关键声明也应为 7 个、339,759 B gzip，旧计数把 app icon 算进了关键路径。

## 已实施的性能修改

1. Mermaid 改为 Markdown fence 生成轻量组件，再在需要图表的页面异步导入引擎。
   首页不加载图表实现；`timeline` 的 SSR 保留可读源码作为加载/失败时的回退内容，并保留深浅色更新。
2. 首页标题和下载 / 快速上手按钮随 SSR 输出即可显示，不再等待水合后解除透明状态。
   演示区域保留有说明文字的 SSR 预览与稳定尺寸。
3. iframe 等主页面加载和绘制完成、演示接近视口后启动，也可由用户主动触发。
   同源镜像须收到真实应用的 ready 消息才移除预览；超时保留重试入口，URL 合并保留 query / hash。
   主题参数覆盖不丢其他参数，主题重载/重试会使旧 iframe 的消息与 load 事件失效。
4. 移除 Google Fonts 的阻塞外链，沿用本地与系统字体栈。
   `Layout.vue` 同步使用 `vitepress/theme-without-fonts`，消除原先间接导入的未使用 Inter 字体及其 preload。
   51.la SDK 在主页面加载后延迟、异步注入，SDK 成功加载后再初始化，同一文档只调度一次。
5. GitHub Star 请求延后且可超时取消；其余功能图接近视口才预热，省流量 / 极慢网络不主动预热。
6. 星空计算与动画延后启动；后台、离屏和减少动态效果偏好下停止持续动画。
   非关键任务有统一取消与清理逻辑，卸载后迟到的 observer/visibility 回调不能重新启动动画。
7. Tailwind 不再扫描独立 demo 的构建产物：在 `custom.css` 中用 `@source not '../../public/demo';` 排除镜像。
   只读差量核验显示扫描从 1,096 个文件降至 93 个；被排除的 1,003 个均属于 demo，
   26 个主题 Vue/JS/TS 文件及原先扫描的 40 个 Markdown 全部保留，没有丢失镜像以外的扫描源。
   修正前至少 2,963 个已生成工具类只来自镜像；最终 CSS 中 `top-[12%]`、`right-[6%]`、`bottom-[8%]` 均已消失。

Tailwind 排除前后的同轮 CSS 分别为 447,325 → 179,116 B raw、69,649 → 33,173 B gzip；
`@layer utilities` 从 260,244 B 降至 4,257 B。最终样式文件是 `style.DYPs82l1.css`，Brotli 为 28,190 B。
这是生产 CSS 的静态差量，不是浏览器加载时间测量。

当前完整演示仍是独立应用，实际体验时仍需要下载它的完整依赖。
此次优化主要改善它与首页关键内容争抢资源的时机，并没有声称演示应用本身已经减小。

## 已实施的 SEO/GEO 修改

- VitePress 与 Vercel 均使用 clean URLs，canonical、sitemap、Open Graph URL 和机器入口保持一致。
- 仅两个实际互译的落地页输出双向 hreflang；关闭默认主题在中文文档中产生的虚假英文页面链接。
- 404 明确 noindex。内部计划与仓库说明排除出公开构建；公开文档可被抓取，`/demo/` 不在文档抓取范围。
- 浏览器标题与社交标题保持一致；统一页面描述、Open Graph / Twitter 元数据。
- JSON-LD 连接 Organization、WebSite、SoftwareApplication、WebPage 等实体；
  技术文档使用 TechArticle 和实际层级面包屑，日期使用已有更新时间，并对嵌入 JSON 做安全转义。
- `llms.txt` 使用真实、可访问的文档入口，说明当前只有中文完整文档。
  下载页的机器 Markdown 从实际 SSR 内容生成，包含当前构建使用的版本、平台下载链接、安装命令与 FAQ，
  同时替换 `llms-full.txt` 的对应段落，避免只输出空标题或 Vue 组件名。
- 支持页也从实际 SSR 导出机器版本，保留微信/QQ 二维码、群链接、联系人邮箱表格和说明，
  其合并文档章节与单页输出保持一致。
- 产品说明和常见问题澄清软件免费与模型服务费用、数据本地优先与向配置服务商发出请求的关系，
  中英文首页同步补充模型、搜索、MCP、云同步和错误报告的数据发送说明，避免绝对化隐私承诺。

没有为 GEO 添加虚构评分、评价、排名或成效数据；结构化数据正确也不保证搜索展示形式或 AI 引用率。

## 验证结果

- `npm test`：**59 / 59** 通过，覆盖原有数据同步/i18n，以及异步任务、SSR 可见性、主题/卸载竞态、无字体主题入口、Tailwind 扫描范围、Mermaid fence、SEO 元数据、下载/支持机器导出和审计逻辑。
- `npm run lint`：通过；`git diff --check`：通过。
- 最终 `npm run build`：通过。外部源不可用时沿用仓库现有 release 数据与 demo 镜像，不能将它解读为已在线核实最新发行版。
- 生产静态审计：**0 错误**；覆盖 25 个 HTML、24 个可索引页面、24 个 sitemap URL、1,248 条站内链接和 24 个机器文件。
- 生产首页无 Mermaid 引擎预载、无 Google Fonts 阻塞外链、无未使用 Inter 预载、无同步统计 script；未出现无效英文文档链接。
- 全部生产页面浏览器标题与 `og:title` 一致；中英文首页 SSR 默认可见且含预览；
  下载机器页面（3,999 B）与支持机器页面（2,250 B）逐字匹配各自 SSR 导出器，并完整包含于合并文档；
  下载链接/安装命令和支持联系人/表格/二维码存在；双语隐私说明更新已进入生产 HTML；时间线 SSR 回退内容存在。

构建仍有两类提示：Node 的 `DEP0205` 弃用警告，以及懒加载图表引擎中大于 500 KB 的 chunk 警告。
后者不再意味着首页预载这些块，图表页实际使用时仍有该成本。本轮没有通过隐藏告警掩盖这两项。

`scripts/bench-site.mjs` 已提供两个版本 × 桌面/移动 × 各 10 次的交替方案，
使用冷缓存、gzip 服务、显式 1.6 Mbps / 750 Kbps / 150 ms 网络参数与 CPU 4 倍降速。
它分别计时真实标题/CTA可用、真实 iframe 控件可用、LCP 和长任务，不把预览算作演示已完成。
默认对两个版本同样阻断第三方请求，并把策略写入报告，避免把不可控外网抖动当作优化收益。

## 浏览器 A/B 结果

`benchmark-final.json` 于 2026-09-27 生成。基线和优化版各自使用独立冷缓存 context，桌面与移动各 10 次，
A/B 交替执行，共 40/40 次通过；第三方请求在两个版本中统一阻断，只比较第一方成本。
「首页可用」要求真实标题、导航和两个 CTA 可见、未遮挡、连续两帧稳定，并通过不触发导航的 DOM 命中检查。
演示则另外要求真实 iframe 应用有内容、存在可命中的启用控件且加载遮罩消失。

| 指标 | 桌面基线 p75 | 桌面优化 p75 | 降幅 | 移动基线 p75 | 移动优化 p75 | 降幅 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 首页可用 | 4,705.8 ms | 1,750.1 ms | 62.8% | 4,496.7 ms | 1,583.3 ms | **64.8%** |
| LCP | 3,437 ms | 1,820 ms | 47.0% | 2,988 ms | 1,611 ms | 46.1% |
| 演示真实控件可用 | 21,699.3 ms | 17,813.7 ms | 17.9% | 35,278.3 ms | 32,091.4 ms | 9.0% |
| 主动体验后演示可用 | 16,420.4 ms | 15,499.6 ms | 5.6% | 30,759.9 ms | 29,906.3 ms | 2.8% |

移动端 10/10 对比样本均通过，首页可用 p75 从 4,496.7 ms 降到 1,583.3 ms，改善 **64.8%**，达到简报中至少 50% 的目标。
完整演示仍是独立应用；延迟启动让首页先可用，但用户主动体验演示时仍有约 29.9 秒的移动 p75 成本，不能把首页改善解读为演示本身变快。

同一报告中的确定性代理指标也下降：移动端总资源编码字节 p75 从 4,992,500 B 降至 3,938,906 B，请求数 p75 从 248 降至 219，
首页可用前主线程阻塞长任务 p75 从 903 ms 降至 470 ms。静态 head 关键 gzip 资源则从 1,162,047 B 降至 120,684 B。

## 环境限制与未覆盖项

这次报告是本地生产静态服务上的实验室结果，不代表线上 CDN、真实第三方服务或 CrUX 用户数据。
页面深浅色、语言切换、Mermaid 最终 SVG、后台/离屏动画和统计送达已有逻辑/静态护栏，但仍应在发布前用真实设备做一次冒烟。
线上旧网址跳转、404 状态与机器入口也尚未验证，因为本轮没有部署。

## 安全回滚思路

性能调度部分可按组件与对应辅助模块成组恢复，再运行测试和生产审计。
Mermaid 回滚时必须一起考虑配置里的 fence 处理、主题注册与异步组件，避免留下无法渲染的标签。

URL / SEO 回滚必须同时处理 VitePress `cleanUrls`、Vercel `cleanUrls`、SEO helper、
canonical / sitemap 以及机器索引中的链接，避免只有某一层退回 `.html` 而造成重复网址或断链。
下载/支持机器导出的 hook 与输出规则也应成组处理，并核对 `llms-full.txt` 中对应段落仍保持一致。

回滚基于本轮明确修改的文件或审核后的提交，不用整目录覆盖当前工作区。
`docs/public/demo/` 及生成器产出的装饰 SVG 不是本轮手改目标，
不要用旧构建副本覆盖这些公共生成产物；涉及镜像或图案时应按原同步脚本/生成器工作流处理。
