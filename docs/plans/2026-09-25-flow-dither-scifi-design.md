# 「使用流程」两张卡的底图：截图换成有序抖动图案

日期：2026-09-25

## 需求

「主页这两个地方的图片得先用这个 Dithering 效果去帮我做一个图案吧。要和我的文本有关的。」
随后补一句：「这个地方能不能做成类似三体的那种感觉？带点科幻感？」

指的是 `StepFlow.vue` 里那两张卡（`#flow`）的 `.pair__shot` ——
原来放的是两张深色 UI 截图（`/home-chat.png`、`/home-anki.png`）。
现在换成与卡片文案相关、带科幻感的抖动图案。

## 结论：图案直接烘焙成 SVG，不在运行时画

hero 的星空层是 canvas 逐帧渲染的，因为它要跟着滚动跑。
这两张是**静态装饰**，没有理由让首页多背一个 canvas、一套渲染循环和两处 resize 监听
—— 用 `scripts/gen-flow-dither.mjs` 一次算完、烘焙成 SVG 落盘，运行时只剩一张 `<img>`。

管线与 hero 完全一致：**先把画面还原成一张 0–1 的灰度场，再用 Bayer 8×8 阈值化成 1-bit 网点**。
阈值取 `(b + 0.5) / 64`，于是灰度 1.0 恒大于任何阈值（整块实心）、灰度 0 恒不点亮，
中间的灰度自动变成「网点由密到疏」。

灰度场不用位图去抖动，而是用解析几何现画（圆角矩形 / 胶囊 / 多边形 / 圆 / 环 / 椭圆弧 / 正弦）。
理由：图案要小、形状要认得出来，边就必须落在网点上。位图缩放后的边被重采样糊成一条灰线，
阈值化出来是一串忽断忽续的碎点。

## 设计

### 两张图各自说什么

| | 文案 | 画面 |
|---|---|---|
| ① 想明白 | 围绕你的材料对话。 | 一颗带环的行星 + 三圈从它荡出去的信号弧 + 右侧摊开的一页材料（正文里有一段被标出，一根引线连回信号） |
| ② 记得住 | 变成能复习的东西。 | 三颗恒星 + 三条斜穿画面、互相交织的轨道弧 + 右下出画的一摞薄片卡（一问两答 + 右上角打勾徽章） |

① 的题眼是那根**引线** —— 对应卡片明细里的「答案带出处」：答案不是凭空来的，它指着材料里的某一段。
② 的题眼是**周期** —— 三体运动的位置是会回来的，复习也是；打勾徽章负责说「复习过了」。

三体那点味道落在三处：铺满全幅的**星图底格**、**扫过画面的轨道弧**、**大小差得开的恒星**。
没有一处写字，也没有搬任何具体作品的元素。

### 画布尺寸不是随手取的

```
① 280×176   1440 视口下窄卡 356px 宽，.pair__shot 取 78% ≈ 278px
② 544×340   1440 视口下宽卡 712px 宽，.pair__shot 取 78% ≈ 555px
```

**画布按显示宽度定**，1px 就是 1px：`CELL = 2`（一个网点 2 CSS px）在 DPR 2 的屏上
正好落在 4 个物理像素上，网点是硬边的。若画布随便定一个尺寸再缩放，
网点会被重采样糊掉，整套效果就没了。

两张图的 `CELL` 一致 —— 网点一样大，只是宽卡那张画幅更宽、容得下更多细节。

### 出画的两条边与溶解的两条边

`.pair__shot` 定位在 `right: -6% / bottom: -8%`：
画布的右边和底边本来就落在卡片外、被卡片的 `overflow` 切掉。

所以渐变只做在**左边和顶边**（`rampAt`），让网点由密到疏自己化掉、给标题让路；
右边和底边留硬边，让图案是「从卡片右下裁进来」的 —— 这一条与旧的截图一致。
四边都溶解的话，图案会缩成一块悬在中间的孤岛。

### 几个绕不过去的坑

- **实心黑块**。灰度拉到 0.9 以上，阈值化出来就是一块墨，与 hero 那套细网点不是一路。
  现在最重的一档压在 0.84（① 行星的暗半），其余主体都在 0.6–0.8。
- **行星的环要拆成两笔画**。整圈一起画，压在球上那一段是「比球淡」的一道，
  读起来是个缺口而不是环绕。正确顺序：后半个（170°→350°，会被球盖住）→ 球 → 前半个（-10°→170°）。
- **Bayer 是 8×8 周期的**。均匀灰度区会天然以 8 行为步长重复，所以 `bake` 除了横向游程合并，
  还叠了一层「与上一行同起止」的纵向归并 —— 大块区域能压成很少的几条矩形，
  产物才停在几十 kB（不合并是几万个 `<rect>`）。
- **窄卡里那张图太小，一多放东西就糊**。① 只有 268px 宽，所以主体只有「球 + 环 + 明暗界线」三样，
  行星的环形山一类碎细节一概不画。

### 接线时的三处改动

1. **`.pair__shot` 去掉投影和圆角**。图案自带透明底，边界是网点自己化掉的；
   投影会沿元素矩形画出一圈看得见的直角边，与图案的收口对不上。
2. **深色下 `filter: invert(1)`**。墨色在文件里写死是近黑 `#1d1d1f`，图案是单色的，
   想要的那张深色图就是它的底片 —— 没必要再存一份深色资产。反相后是 `#e2e2e0`，
   与站点深色正文（`--lp-text` `#f5f5f7`）差三级，网点上看不出来。
3. **`sampleTone()` 采样前先铺一层卡片底色**。加号钉在卡片右下角，颜色照底下那块采。
   底图现在是透明底的图案，而右下角那一块本来就几乎没墨 —— 直接采样一个不透明像素都取不到，
   于是 `+` 按「暗底」做成白圆，落在浅色卡面上等于看不见。铺上底色之后，
   采到的才是加号底下**真正**的颜色（图案稀疏时就是卡面本身）。
   顺带补一个 `watch(isDark)`：卡片底色跟着主题走，切主题要重采，否则深色下黑圆会糊进卡面。

## 验证

无头 Chrome（CDP），dev server 5175：

| 场景 | 结果 |
|---|---|
| 1440×900 浅色 | 两张图案就位，`+` 档位 `light,light`（黑圆白加） |
| 1440×900 深色 | `+` 档位 `dark,dark`，`.pair__shot` 计算样式 `filter: invert(1)` |
| 390×844 移动端 | 图 239×150（0.85 倍），网点仍清晰；单列布局正常 |
| 点开卡片 | 浮层里放大到 720px，网点变粗但形状与层次仍成立（1-bit 放大就是这个味道） |

- 图案本体的墨迹范围用 canvas 量过，与设计坐标逐一对齐：① `(16,20)–(233,153)` / ② `(48,8)–(481,321)`。
- `npm test`：全部通过。
- `NODE_OPTIONS= npx vitepress build .`：build complete，无新增告警。

截图存在 `plans/flow-dither/shots/`，对照原型页在 `plans/flow-dither/preview.html`
（相对路径引用 `docs/public/` 里那两张图，直接双击可开）。

## 已知未做 / 取舍

- **`/home-chat.png`、`/home-anki.png` 没有删**。它们已经没人引用了，但这一版是「先做一个图案」，
  真要回退还来得及；确认不再回头之后再删。
  （`/home-mindmap.png`、`/home-quiz.png` 仍被功能区轮播用着，与本效果无关。）
- **图案不跟随主题换墨色，靠 `invert`**。想做真正的两套墨色就得存四份资产、
  再在组件里按 `isDark` 挑 `src`；现在这份代价只有一行 CSS。
  代价是图案被反相后，`#1d1d1f` 变成 `#e2e2e0` 而不是站点深色正文的 `#f5f5f7` ——
  单色网点上这一档差不出来，但如果将来图案里出现第二种颜色，这条就得重做。
- **浮层里放大会变粗**。SVG 的固有宽度就是窄卡里的显示宽度（280 / 544），
  在 720px 的浮层里是 2.6 倍放大，网点从 2px 变成 5px。这是 1-bit 图放大的必然结果，
  不是缺陷，但如果不喜欢，只能给浮层单独出一份大尺寸资产。
- **没有画「三体」的任何具体形象**。只有星图、轨道、恒星这类通用语汇，
  既是版权上的克制，也让图案在窄卡尺寸下读得出来。
