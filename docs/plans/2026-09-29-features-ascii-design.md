# 功能区四扇窗口屏：有序抖动网点换成字符画

日期：2026-09-29
前置：`2026-09-26-features-dither-design.md`（这一版取代了它的底图部分，构图与题眼沿用）、
`2026-09-28-flow-ascii-design.md`（字符画这套的口径与全部踩坑）

## 需求

「四件事，装进同一个窗口。资料对话、知识导图、题目练习、Anki 制卡共用同一份数据，
不用在几个软件之间来回搬。这四个画面，有没有必要变成 ASCII / 字符画风格。
请你把这几个也变成 ASCII / 字符画风格。要求也要适配黑夜模式。」

指的是 `#features` 那张轮播卡右半的 `.lp-win__screen`（`HomePage.vue`）——
之前放的是 `scripts/gen-features-dither.mjs` 烘焙的有序抖动网点 SVG。

## 有没有必要：有必要，理由是统一而不是好看

`90ac2a9` 已经把「使用流程」两张卡换成了字符画，于是首页上同时存在**两种**
「机器画图」的质感：流程区是字符，功能区是网点。两者的题材、手法、笔触完全不同，
用户不会分析，但会读成「这两块不是一套东西」。

字符画还有一个网点没有的性质：**它每一格都是可数的选择**。网点是把一张连续的灰度图
抖成点阵，放大之后仍然是「一张被降采样的图」；字符画放大之后仍然是「一个一个画上去的
字」。对一个文档站来说后者更诚实 —— 图案不需要假装自己是照片。

代价是明说清楚的：字符画一格只有 6 × 11，452px 宽的屏上是 75 列，比网点粗得多，
渐变与细密纹理画不出来。所以它只适合**符号**级别的构图 —— 而这四张本来就是符号
（一张纸 + 一个气泡、一棵树、一张卷子 + 一枚徽章、一摞卡 + 一条曲线），
题眼（引线 / 层级 / 判分 / 遗忘曲线）全是大形，8 档够用。

顺带一个不是理由但是结果的便宜：四张 gzip 从 19.3 kB 降到 10.0 kB。

## 结论：管线整套换成字符画，但**不内联**

| | 上一版 | 这一版 |
|---|---|---|
| 格子 | 网点，2 × 2 CSS px | 字符格，6 × 11 CSS px |
| 落地方式 | Bayer 8×8 阈值化成 1-bit 网点 | 每格量化成 8 档，各挑一个字符 |
| SVG 图元 | 一条 `<path>`，全是矩形子路径 | 八条 `<path>`，全是**描边** |
| 画布 | 452 × 282 | 450 × 286（75 × 26 格） |
| 灰度场 | 解析几何现画 | 同一套，没动 |

### 深色模式：结构上就成立，不需要反相

那扇窗是**一块设备屏幕**，不是页面的一部分。屏底 `--fc-screen: #1f2021`
是从四张真截图（`home-chat` / `home-mindmap` / `home-quiz` / `home-anki`）
的主色 rgb(31,32,33) 采出来的，两套主题共用、不进 `.dark`；窗口壳
（`--fc-win-bar: #f2f2f4`）同理。浅墨 `#e8e8ea` 打在 `#1f2021` 上对比度约 14:1，
浅色主题与深色主题下是**同一张图**，都不需要 `filter: invert(1)` ——
也就没有「反相出来的灰和站点正文色对不上」这回事（`#e2e2e0` vs `#f5f5f7`，差三级）。

实测两套主题下四扇窗完全一致，见文末截图。

### 不内联：这一处与「使用流程」相反，是有理由的

`2026-09-28-flow-ascii-design.md` 的「后续」把流程那两张从 `<img>` 换成了内联 SVG，
理由是**必须**内联：`currentColor` 只在宿主文档里才解析得到页面的主题色，
不内联就只能挂 `filter: invert(1)`。

这四张不需要 —— 浅墨两套通用，`currentColor` 对它没有价值。而内联要付的账是实的：
四张 SVG 合计 64 kB 原文 / 10 kB gzip，会整份进落地页的 chunk，
其中**三张是用户可能一辈子不看的**（轮播一次只显示一张）。`HomePage.vue`
里那段 `warmSceneImages()` 预热就是为「按需加载」留的，保留 `<img>` 就不用动它。

| | 内联 | `<img src>`（选的） |
|---|---|---|
| 落地页 chunk | +10 kB gzip，无条件 | +0 |
| 首屏请求 | 0（已内联） | 1 张，按需 |
| SSR 首帧 | 有图 | 只有当前那张（另三张懒加载） |
| 换主题 | `currentColor` 自动跟 | 不需要跟（屏本来就是深色） |

## 设计

### 四张共用一个 `viewBox`，不裁到墨迹

`wrapAscii` 默认把 `viewBox` 裁到墨迹 + 一圈等宽留白。那对**各自独立**的图是对的
（打开就是一张居中的图），对这四张不行：它们是**轮播**，同一块屏里轮换显示。
各自裁一次之后 viewBox 的长宽比各不相同（实测 438×220 / 450×242 / 402×220 / 420×249，
比例 1.69 ~ 1.99），屏盒是固定的一个比例，`object-fit: cover` 只好把每张各自缩放 ——
**切一下 tab 图案就跳一下大小**。

所以给 `wrapAscii` 加了 `opts.crop: false`：固定 `0 0 450 286`，四张严格同尺同位。
代价是留白由构图自己负责，于是 `bake()` 每次跑都量一遍「墨迹中心与画布中心的偏差」，
超过半格（横 3px / 纵 5.5px）就说明这张偏了。

### 偏了怎么办：整张按格挪，不重算坐标

构图是照 dither 那一版的绝对坐标搬过来的，搬完必然有一两张偏个十几像素
（首轮实测 chat +6/−11、quiz −12/−11、anki +15/+7）。与其把上百个坐标挨个重算，
不如搬完之后整张挪一下 —— `shift(pairs, cols, rows)`，位移的**单位是格**（6 × 11）。

必须是格：字符画最硬的一条约束就是形状压在格线上，平移半个格子会让每一格的覆盖率
重新算一遍，描边边上立刻挂出一圈毛边。收的是 `[形状, 档位]` 的数组而不是单个形状 ——
档位与形状一一对应，拆开再配对迟早配错。

为此给 `lib/dither.mjs` 的 `shape()` 加了 `export`（字符画那边要自己 new 一个平移过的
`{ bbox, hit }`）。

### 字符格是离散的：四处必须量化成格子

这一版的构图里有三样东西是几何原语画不出来的，都换成了「先量化成格子再画」：

1. **斜线与曲线 → `trace()`（Bresenham 走格子阶梯）。**
   格子是 6 × 11 的长条，一根等宽斜线穿过去，每格吃到的面积在 0.2 到 0.7 之间摆动，
   被 `COV_KNEE` 放大成两三档的明暗差 —— 画出来是一串毛刺而不是一根线
   （第一版把线加粗到 20 都压不平这件事）。量化成格子之后覆盖率恒为 1：
   斜线就是「一格一格地走」，这正是字符画里斜线本来的样子。
2. **圆环 → `ringCells()`（按格心采样成整格）。**
   几何环带（`ring`）的厚度按 px 给，格子却是长条：环走到 45° 时一个格子横跨环的
   内外两侧，覆盖率在 0.2 到 0.9 之间跳 —— 厚 24 是一圈断断续续的散点，厚 33 糊成实心圆盘。
   同心圆也试过：只是「1 格宽的线」，两个圆的间距在 12 点方向是 11px、3 点方向是 6px，
   补到三圈仍在斜向露缝。
3. **气泡尾巴 → 逐行加宽的阶梯三角**，不是几何三角。三角的两条斜边同样会被覆盖率
   折成浅档（`-`），尾巴尖那里会散成一撮灰点。

另外三处沿用流程那两张的硬约束：**横条吃满一整行**（y 取 11 的倍数）、
**竖条骑在列的分界线上并占两列**（x 取 6 的倍数）、**圆点用压扁的椭圆**
（`ellipse(cx, cy, CELL_W, CELL_H / 2)`）而不是正圆。

### 没有边缘溶解

dither 那一版四边都挂了缓坡（约 30px），名义是「硬边界交给窗口壳，图案在屏里浮着」。
字符画这边不需要，也不该要：溶解做在**档位**上，一条横跨形状的缓坡会把描边的一侧
整体压低一两档 —— ① 的纸、③ 的卷子都是一整圈闭合的描边，四边同时被压、深浅各异，
读起来是画错了，不是「长出来」。「浮着」由固定 viewBox 与屏底色天然给到。

### 明度分配：主次照旧，只是「底」更靠下

沿用 dither 版的教训：**纸是底、不是主体**。① 的纸描边 0.5 / 正文 0.6 / 高亮条 0.9；
③ 的卷子 0.5 / 页眉 0.7 / 题号块 0.85 / 题干 0.68 / 选项 0.5、选中 0.9。
② 的题眼是层级（根 0.92 / 一级 0.66 / 二级 0.44），三级明度差本身就是「结构」。

改了一处：④ 后两张卡的 L 形从 0.3 提到 **0.52**。0.3 出来的是一撮散在左上角的 `-`，
读起来像划痕而不是「后面还压着两张卡」；0.52 落在 `+` 上，与最前面那张的描边（0.5）
同量级 —— 仍然是「底」，但那三条边确实是在那儿。

另外三张卡片堆仍只画**左边 + 顶边**那截 L 形：字符画没有「盖住」这回事
（`paintInk` 的 tone 取 max，两层只会变深），三张完整描边叠起来，后面两张的底边
会横穿最前面那张的内部，读成一团。

### 接线时的改动

1. **文件名**：`feature-*-dither.svg` → `feature-*-ascii.svg`（中英两份消息表都改）。
2. **`alt`**：`材料与对话引线的抖动图案` → `…的字符画`，英文
   `Dithered artwork of …` → `Character art of …`。
3. **`.lp-win__screen` 的 `aspect-ratio`**：`452 / 282` → `450 / 286`，跟着资产走。
   1440 视口下屏盒实测 452 × 287.3，比画布宽 2px（0.44%），是一处**均匀**缩放 ——
   字符笔画不落在非整数像素上，看不出来（网点那边同样的偏差会挂出一圈灰边，
   `85830aa` 就是为这个把比例改成照资产取的）。
4. **删掉 `scripts/gen-features-dither.mjs` 与四张 `-dither.svg`**，照 `gen-flow-dither.mjs`
   被字符画取代时的做法。`docs/plans/2026-09-26-features-dither-design.md` 留着当记录。
5. **`agents.md`** 里那两处（产物清单、生成器清单）跟着改。

|---|---|
| 1440 视口 `.lp-win__screen` | 452.0 × 287.3，比例 1.5735（资产 450/286 = 1.5734） |
| 390 视口 `.lp-win__screen` | 302.0 × 191.9，比例 1.5734，与桌面同一个比例 |

| 各档字符数 | 四张都真的用满了中段档位，没有一档是空的 |
| 体积 | 四张 gzip 19.3 kB → 10.0 kB |
| 产物 | `dist/` 里只剩 `-ascii`，`-dither` 0 个 |
| 首页 SSR | 只有当前那张的 `<img>`，另三张仍靠 `warmSceneImages()` 按需预热 |

截图在 `plans/features-ascii/shots/`（1440 浅/深 + 390 浅/深 + 逐场景），

两次 `paintInk` 叠出来、④ 的曲线峰值三次都回到同一条水平线上 —— 都对得上。

## 已知未做

- **屏底色仍是 `--fc-screen` 写死在一个值上。** 换成两套主题各一档要多一个变量，
  但屏本来就不参与主题切换，写了也是摆设。
- **`shift()` 只能按整格挪**，居中精确到半格。要更准只能回到逐个坐标重算，
  收益（1.5px）不值那个改动量。
