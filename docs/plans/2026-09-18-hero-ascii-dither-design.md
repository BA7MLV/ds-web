# Hero 底图：有序抖动改成 ASCII 字符点阵（已废弃）

日期：2026-09-18
状态：**已废弃，同日回退** —— 回退说明见文末

## 需求

「当前 hero 的 Dithering 效果我希望是 ascii 字符【D,e,e,p,S,t,u,d,e,n,t】组成的。」

即：抖动点阵里「亮起来的点」不再画成实心方块，而是画成 `DeepStudent` 这 11 个字符之一。

## 关键结论：坐标系必须整体换掉

上一版（见 `2026-09-16-hero-starfield-design.md`）是逐**离屏像素**做 1-bit 阈值化：
`SCALE = 0.5` 把画布缩到一半，再用 `image-rendering: pixelated` 放大回全屏 ——
一个网点是 2 CSS px 见方的硬边方块。

这个尺寸下任何字形都糊成一团墨点，「由字符组成」根本看不出来。
字符要认得出来，格高至少 10 CSS px，是原网点的 5 倍。于是：

| 维度 | 上一版 | 这一版 |
|---|---|---|
| 阈值化单元 | 离屏像素（2 CSS px） | 字符格（7 × 11 CSS px） |
| 画布分辨率 | 0.5 倍 CSS，pixelated 放大 | 1 倍 CSS × DPR（上限 2），平滑放大 |
| 每帧写入方式 | 逐像素写 `imageData` 的 alpha 通道 | 预渲染字符 tile + `drawImage` 贴图 |
| 星点半径单位 | 离屏像素 | 格（距离按 cellW / cellH 归一化） |

**没有变**的：滚动编排（`--sf-y` / `--sf-dim` 两段 easeInOutSine）、层间视差、
`prefers-reduced-motion` 降级成静态层、闪烁模型（每颗星独立相位/角速度）、
主题分叉规则（密度场暗角只在亮色铺）、`.sf` 的层级与挂载位置。

## 设计

### 字符格

- 格高 `CELL_H = 11`（CSS px），是这套效果的主控旋钮。
- 格宽**不写死比例**，由 `measureCellW()` 用 `measureText('D')` 量出等宽字体的推进宽度
  再留 1px 字距。写死比例的话，字体落到系统兜底字体时字符会左右粘在一起。
- 字符按**线性索引**取：`tiles[(gy * cols + gx) % 11]`。同一行读下来是连续的
  `DeepStudentDeepStudent…`，而不是随机撒字 —— 这是唯一一处「看得出来是这串字符」
  的地方，随机取的话整片就只是噪点。

### 逐帧两步

1. **亮度场**：以每颗星为中心，只遍历它包围盒内的格子，把抛物光斑叠进
   `Float32Array(cols * rows)`。距离按格宽/格高归一化 —— 格不是正方形，
   不归一化光斑会拉成椭圆。开销跟「星数 × 单星覆盖格数」成正比（约 600 × 4）。
2. **阈值化 + 贴图**：逐格算 `grid[i] * mask[i] + field[i]`，跟 Bayer 8×8 比，
   过阈就 `drawImage` 贴一个字符 tile。开销跟格数成正比（约 206 × 82）。

### 为什么用 tile + drawImage，不用每帧 fillText

一帧要点亮的格子数量级在 1e3，`fillText` 每次都要走字形解析与光栅化，
30fps 下是十几万次/秒。字符集只有 11 个、格尺寸固定，光栅化一次存成小 canvas
之后只做贴图，快一个量级。

### 参数重新标定（都是实测出来的）

| 参数 | 上一版 | 这一版 | 依据 |
|---|---|---|---|
| `STAR_PER_PX` | 1/12000 | 1/2600 | 格面积是原网点的约 25 倍；1/4000 时整屏只剩零星几粒 |
| `MAX_STARS` | 460 | 2000 | 跟着密度上限走 |
| 星点半径 | 0.9～4.8 离屏 px | 0.65～2.5 格 | 下限 0.6 格：再小的话格中心采样点落在光斑外，一颗星一个字符都点不亮 |
| `BRIGHTNESS` | 无 | 0.8 | 半径放大后同一份 amp 会让亮星中心整片过阈（实心块而非网点），压到 1 以下才留得住边缘的抖动渐变 |
| `INK_ALPHA_LIGHT` | 0.3 | 0.45 | 上一版点亮的是实心方块，字符是细笔画，同样不透明度下视觉重量掉一大截 |
| `INK_ALPHA_DARK` | 0.45 | 0.55 | 同上；深色没有外圈暗角，全靠星点撑厚度 |

## 验证

### 1. 参数扫描（独立页面）

用一份把渲染算法原样搬出来的独立页面（参数走 query，随机数换成固定种子）
在 1440×900 无头 Chrome 下扫描：

- 字符尺寸：9 / 11 px —— 9 已经勉强，11 清晰，取 11。
- 密度：1/4000 / 1/2600 / 1/2200 —— 1/2600 是「看得出是字符、又不吵」的拐点。
- 墨色：亮色 0.3 / 0.45 / 0.58，暗色 0.45 / 0.6 —— 取 0.45 / 0.55。
- 2× 放大截图确认字形完整、抗锯齿正常，没有糊成块。

## 已知未做 / 取舍

- **读不出单词**。字符是按索引循环取的，整片是「由这 11 个字符组成的噪点」，
  不是「背景里铺着一句 DeepStudent」。如果要做成后者，得改成按行重复平铺整串文本，
  再用同一个亮度场当遮罩 —— 是另一套做法，没做。
- **网点粒度粗了 5 倍**。原来那种细密网点质感没了，这是字符可读性的必然代价。
  想要更细只能缩格，但缩到 9px 以下字形就开始糊。
- **站点本身没构建成功过**（原因见上），SSR 那一段是按代码路径推的：
  `document.createElement` 只出现在 `measureCellW` / `buildTiles` 里，两者只由
  `build()` 调用，而 `build()` 只在 `onMounted` 里跑 —— SSR 阶段不执行 DOM API。
  结论可靠，但没实测。
- **性能没在真机验证**。桌面无头 Chrome 下正常；iPad Safari 上的帧率未知。
  画布总像素按 6e6 封顶，大屏会自动降 DPR。
- 只改了 Hero 这一处；`docs/public/demo/` 是另一个工程的构建产物，与本效果无关。

## 回退（2026-09-18 当天）

看过效果后决定不做：「算了不要用 ascii 字符【D,e,e,p,S,t,u,d,e,n,t】组成的。」

`HeroStarfield.vue` 已按原样还原（489 行，网点实现一字未改，还原后用无头 Chrome
跑过一轮：`errors: []`、切主题/resize/卸载均正常、画面回到外圈网点暗角 + 中间星点）。
字符版代码留档在 `/tmp/HeroStarfield.ascii-dither.vue`（临时目录，随时会没）。

这份文档留着，是因为下面两条结论跟具体用哪串字符无关，下次再想动这块还会撞上：

1. **字符可读性 ⇔ 网点粒度，只能二选一。** 格高低于 10 CSS px 字形就开始糊，
   而 10 px 是原网点（2 CSS px）的 5 倍 —— 只要想做字符抖动，就必然接受
   「网点粗 5 倍」，原来那种细密网点的质感回不来。
2. **密度与墨色必须重新标定，不能沿用。** 字符是细笔画，同样不透明度下视觉重量
   比实心方块掉一大截；颗数不变的话覆盖率只剩约 1/25。实测拐点：
   `STAR_PER_PX` 1/2600、`MAX_STARS` 2000、亮色墨色 0.45、暗色 0.55、
   新增 `BRIGHTNESS` 0.8（不压这一档，亮星中心会整片过阈变成实心块）。
