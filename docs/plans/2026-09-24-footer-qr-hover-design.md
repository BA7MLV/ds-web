# 页脚二维码浮层：QQ / 小红书悬停弹码

日期：2026-09-24

## 需求

「想要当前的底部滑动到 QQ 和小红书都输入的时候，会显示这个。显示我们 QQ 群的二维码还有小红书的二维码。」

「这个」指的是一份 hover 弹图原型：触发词从文字中心缩放长出一张图，图还带一点鼠标跟随。
诉求是把它接到页脚那排图标上 —— 悬停 QQ / 小红书时弹出对应二维码。

两处决策先确认过：

1. **二维码来源**：用页脚已有的链接现场生成（`https://qm.qq.com/q/1lTUkKSaB6`、
   小红书主页 URL），不占用户出图的时间；将来换官方图只需替换 `docs/public/` 下同名文件。
2. **触屏行为**：点一下弹码，而不是直接跳走 —— 直接跳走的话用户永远看不到码。
   跳转改由浮层里的「打开链接」承担。

## 为什么不能照搬原型

原型的触发词是正文里的行内文字，四周都是空的。页脚图标不满足这个前提：

- **图标钉在视口右下角。** 卡片宽 184px，居中展开时右边缘会顶出视口：
  小红书那枚中心距右边只有约 68px（它右边还压着 email 图标），184/2 = 92 > 68。
  溢出量随视口宽度变化，靠调 `translateX` 的魔法数字压不住。
- **卡片必须往上长。** 图标中心距视口底边只有 58px，往下没有空间。
- **触屏没有 hover。** 原型整个动效挂在 `:hover` 上，触屏要么看不到，要么被浏览器
  的 hover 模拟卡住（点一下 hover 状态一直保持，第二次点收不起来）。

## 设计

### 一、几何：右对齐图标中心，`transform-origin` 挪到右下角

放弃「居中向四周展开」，改成**卡片右边缘落在图标中心 +14px**（+14 是图标半宽，
即右边缘压住图标中线），向左上展开。

```css
transform: translate(calc(-100% + 14px), calc(-100% - 12px)) scale(.05);
transform-origin: 100% 100%;
```

- 右对齐后，卡片右边缘永远在图标右边缘附近，**与视口宽度无关，不溢出** ——
  不需要任何按断点写的补偿值。
- `transform-origin` 必须跟着从 `50% 50%` 改成 `100% 100%`。原点落在卡片右下角，
  缩放才像「从图标那个点抽出来」；留在中心的话卡片会先在左上方凭空长大、
  再平移过去，看着像两张卡。
- 垂直 `-12px` 是卡片与图标之间的缝，避免卡片压住图标本身。

### 二、三层结构：平移与缩放分开

沿用原型的分层，理由也照旧 —— 两条曲线的回弹感不一样，合成一个 `transform`
会互相拖累：

| 层 | 职责 | 曲线 |
|---|---|---|
| `.lp-qr` | 0×0 锚点，钉在图标中心 | 无 |
| `.lp-qr__follow` | 只吃鼠标偏移 `--dx` / `--dy` | `cubic-bezier(.18,1.7,.34,1)` .55s |
| `.lp-qr__card` | 显隐 + 缩放 | 同上曲线 .62s + opacity .22s |

跟随幅度**刻意收得比原型小**：水平 ±26px、垂直 ±10px（原型是 ±70）。
页脚贴着视口右下角，跟满会把卡片直接甩出屏幕。

### 三、触屏：换一套定位，不换 DOM

用 `@media (hover: none)` 把浮层从「贴图标」切成**视口居中 + 半透明遮罩**：

- 页脚图标在窄屏下贴左边缘（`<520px` 时 `.lp-footer__bottom` 变纵向），
  沿用「右对齐图标」必然有一侧出界；居中之后 220px 的卡片在 320px 宽的屏上也放得下。
- 遮罩点击关闭，再点图标也关闭。
- 卡片里多一枚「打开链接」，接住被拦下的跳转。

**展开规则整体包在 `@media (hover: hover)` 里**，包括 `:focus-within`。
不加这层的话，触屏点一下会被浏览器模拟成 hover 并一直保持 ——
「再点一次收起」永远收不起来，点击逻辑和 hover 直接打架。

### 四、跳转拦截

```js
if (!item.qr || isPointerHover()) return
event.preventDefault()
openKey.value = openKey.value === item.key ? null : item.key
```

- 桌面端 hover 已经能看到码，点击照常跳转，**不拦**。
- 触屏第一次点击拦下亮码，第二次点同一枚收起。
- `matchMedia` 的结果**不缓存**：只在点击时读一次，省下的开销换不来
  「窗口从触屏切到桌面后判断失效」这类怪 bug 的成本。

### 五、卡片底色恒为白

二维码反色后多数扫码器认不出，所以卡片背景写死 `#fff`、文字写死 `#55555c`，
**不接 `--lp-text` 系列变量**，深色主题下也是白卡。代价是深色页面上出现一块亮面，
但这是「实物」该有的样子，不是配色失误。

### 为什么要收窄 `.lp-footer__links a`

浮层挂在 `.lp-footer__links` 底下，原来的后代选择器 `.lp-footer__links a`
会把里面的「打开链接」一并套上 28×28 的图标样式。收窄到 `> li > a` 把两者分开，
同时保持原样式的作用对象不变。

### 为什么浮层挂在 `<li>` 上而不是 `<a>` 里

触屏浮层需要一枚「打开链接」，而 HTML 不允许 `<a>` 嵌套 `<a>`。
把浮层作为 `<a>` 的**兄弟节点**放在 `<li>` 里，嵌套问题自然消失，
桌面端的 `:hover` 触发也从 `<a>` 挪到 `<li>` —— 两者尺寸相同（都是 28×28），行为不变。

## 已知未做 / 取舍

- **卡片不可点。** 桌面端卡片 `pointer-events: none`：卡片一旦能接鼠标，
  hover 会在鼠标移出 28px 图标时断掉、码当场收起，根本移不过去。
  想要「点码跳转」得换一套触发机制（例如 pin 住），没做。
- **触屏浮层没有 ESC / 焦点陷阱。** 它不是模态对话框，没有 `role="dialog"`，
  也没做焦点管理。当前只有遮罩点击与再点图标两条关闭路径。
- **跟随在触屏下不生效**（没有 `mousemove`），`--dx/--dy` 恒为 0，卡片纯居中。
- **`.lp-qr__img` 的尺寸写死在 CSS**（160px）。二维码是位图，改尺寸要同时
  确认生成脚本的 `TARGET_PX` 留够余量。
- **官方二维码图片未替换。** 当前两张是从公开链接生成的通用码，
  扫码可用，但不是品牌化的分享图。
