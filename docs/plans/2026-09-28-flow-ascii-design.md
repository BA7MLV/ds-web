# 「使用流程」两张卡的底图：有序抖动换成字符画

日期：2026-09-28
前置：`2026-09-25-flow-dither-scifi-design.md`（这一版取代了它的底图部分，构图沿用）

## 需求

「可不可以把想明白 · 围绕你的材料对话 / 记得住 · 变成能复习的东西，这个里面的图
变成 ASCII / 字符画风格。」

指的是 `StepFlow.vue` 里那两张卡（`#flow`）的 `.pair__shot` —— 之前放的是
`scripts/gen-flow-dither.mjs` 烘焙的有序抖动网点 SVG，现在换成字符画。

## 结论：还是烘焙成 SVG，只是把「阈值化」换成「量化成字符」

hero 的星空层是 canvas 逐帧渲染；这两张是静态装饰，运行时只留一个 `<img>`。
沿用这条口径，不动。

变的只有最后一步：

| | 上一版 | 这一版 |
|---|---|---|
| 格子 | 网点，2 × 2 CSS px | 字符格，6 × 11 CSS px |
| 落地方式 | Bayer 8×8 阈值化成 1-bit 网点 | 每格量化成 8 档，各挑一个字符 |
| SVG 图元 | 一条 `<path>`，全是矩形子路径 | 八条 `<path>`，全是**描边** |
| 灰度场 | 解析几何现画 | 同一套，没动 |

`lib/dither.mjs` 那套「不拿位图去抖动、每格超采样求覆盖率」的理由在字符画上依然成立，
而且更要紧 —— 字符只有八个、每格只能挑一个，形状的边必须干净地落在格子上。

## 设计

### 字符梯度是量出来的，不是挑出来的

```
RAMP = ['.', ':', '-', '=', '+', '*', '#', '@']
```

挑字形只看一件事：**落在格子里的一笔有多长**（笔宽固定 1.27）。八档的覆盖面积
大约是格面积的 0.2% / 0.8% / 8% / 15% / 22% / 35% / 44% / 56%，步长均匀。
八个字形全部写死成矢量笔画，**不用 `<text>`**：这两张图被 `<img>` 引用，
`<text>` 的字体由系统字体栈解析，macOS 的 Menlo 与 Windows 的 Consolas 度量不同，
字体缺失还会退回别的等宽体 —— 同一份文件在不同机器上画出来的不是同一张图。

### 覆盖率与墨量必须分开记

dither 那边 `paint` 把两者混成一个灰度值（`field = field*(1-cov) + tone*cov`）再阈值化，
这是对的：灰本身就同时表达了「多黑」和「占了多少」。

字符画不能这么混。混完再量化，形状的**边缘格**因为覆盖率只有一半、墨量也被打了折，
量化出来比内部浅一档 —— 整条轮廓变成「亮边」，读起来是描了个边的空壳。
所以 `paintInk` 把 `cov` 与 `tone` 分两个数组记，`levelAt` 里再按
「覆盖率补足」（`min(1, cov / 0.55)`）合起来。

### 气泡不填实

字符画一格只有一个档位。实心的气泡会把轮廓和内部画成同一档，整块读出来是一片
均匀的字，气泡的形状反而糊掉 —— 这一版头两轮就是这么糊的，卡面上只剩一个方块。

气泡改成**描边**（`hollow(外圈圆角矩形, 内圈圆角矩形)`，为此给 `lib/dither.mjs`
加了 `hollow`）。描边把「有边界」和「有内部」分成两件事，再加上问号那一档最重的墨，
三层重量从浅到深排开，符号才立得住。

### 三处必须对齐字符格的地方

这是字符画与网点图最大的差别：**网点是无限细的采样，字符格是离散的**，
一个形状「刚好压在格子上」和「偏半格」画出来是两个东西。

1. **气泡框的描边宽 11px = 整整一行，两条边都落在行的分界线上。**
   窄于一行，上下两条边落不满格子，覆盖率补足也救不回来，边框从实线变成虚线；
   对不齐行边界，一行被吃满、邻行只吃到一角，那一角被按覆盖率打折、画成浅一档的字 ——
   边框上会挂出一条毛边。
   左右方向一格只有 6px，同一条描边折过去是 1.8 格，比上下厚一点，
   这是 6 × 11 的格子必然的结果，看起来是「框比横厚」，不像瑕疵。
2. **问号的竖与点骑在列的分界线上（横坐标取 6 的整数倍）。**
   笔宽 9 跨两格时，压在分界线上两格各吃 4.5px、覆盖率 0.75 —— 越过 `COV_KNEE`，
   两格都按满档画成实心的 `@`。偏半格就变成「一格满、两格各吃一角」，
   那两角被按覆盖率打折，画出来是一对浅字，整根笔画看着是毛的。
3. **问号的「点」是压扁的椭圆，不是圆。**
   字符格是 6 × 11 的竖长条，正圆点要么横向伸进邻格、要么竖向占不满，
   两种情况都被覆盖率打折（试过：`<circle r=5.5>` 被摊到相邻四格，
   量化出来是一小片浅字，放大看是散的）。改成占满两格宽、一行高的椭圆
   （`ellipse(cx, cy, CELL_W, CELL_H / 2)`），正好两个实心 `@` —— 才读得出是个点。
   为此给 `lib/dither.mjs` 加了 `ellipse`。

### 问号的钩要采样成折线，不能用 `arcRing`

`arcRing` 的两端是**径向的薄片**：在 168° 那一端，薄片几乎是水平的，
落进格子里只有 0.08 的覆盖率，被 `COV_MIN` 吃掉，钩的左下起笔就断了，
问号读成了「n + 一竖」。改成沿弧采样成 `polyline`（步长 6°，r=20 时每段弦长 2px，
远小于 9px 的笔宽）—— 每一段都是带圆头的胶囊，两端自然是圆的，起笔落得住一个格子。

弧的张角也从上一版的 190°→455° 改成 168°→450°：上一版两端几乎接上、圆成了圈，
放大看是个「6」；现在缺口留在左下，是问号该有的开口方向。

### 覆盖率门槛比 dither 那边高一个量级

`COV_MIN` 取 0.15（dither 那边是 0.05）。dither 里「擦到一点」的格子点亮一个网点、
正好当抗锯齿用；字符画里同一格会被画成**一个完整的字**，哪怕是 `:` 也有实体。
所以笔画末端的圆帽压到下一行的一角（覆盖率 0.08 上下）会凭空多出一排浅字 ——
问号的竖与点之间本该空着，那里却冒出一排 `::`，看着像噪点。
0.15 把这些「只擦到一点」的格子收干净，同时不影响任何一笔主体（最细的笔画
覆盖率也在 0.6 以上）。

### 没有边缘溶解

dither 那一版在左 / 上挂了缓坡，名义是「让图案从卡面里长出来」——
但那两张图的主体都离画布边很远（气泡左边空 4 格、右边还空 4 格），缓坡根本没碰到图案，
只有注释以为它碰到了。

字符画这边更不该挂：溶解做在**档位**上，一条横跨形状的缓坡会把边框的一侧整体
压低一两档 —— 上下两条边一个深一个浅，读起来是画错了，不是「长出来」。
深度感交给各自的渐变（`frameTone` / `loopTone`），那是沿对角线走的，
两边都有深浅，眼睛认它是光，不认它是缺陷。

### 拖尾与箭头

- ① 的尾巴仍是一个实心三角，跟框同档（略压到 0.72），读起来才和框是一个整体。
- ② 的箭头是实心三角，压到 `#` 一档：满档的 `@` 会在环的右上角糊出一根九格宽的
  实心横杠，比环里那个对勾还抢眼。

### 接线时的两处改动

1. **`.pair__shot--0` 的宽度 72% → 84%**。字符画一格只有 6.5px，按 72% 铺上去
   字被压到 5px 上下、字形开始糊；放大一圈让笔画落在 13 个物理像素上。
   （① 的图从 256×163 变成 299×191，仍在卡片内边距里。）
2. **`alt` 与文案跟着改**：`单个问答气泡的抖动图案` → `单个问答气泡的字符画`，
   英文 `A single dithered question bubble` → `A single ASCII-art question bubble`。
   文件名也从 `flow-*-dither.svg` 改成 `flow-*-ascii.svg`。

## 后续：从 `<img>` 换成内联 SVG（2026-09-28 同日）

需求补了一句：「然后我希望这个不是图，而是 svg，可以适应黑夜模式。」

底图本来就是 SVG，但这句戳到的是实情：原先它是 `<img src="…svg">`，
**`<img>` 里的 SVG 是一份独立文档** —— 页面切深色它不知道，只能给元素挂
`filter: invert(1)`，把写死的 `#1d1d1f` 反成 `#e2e2e0`，与站点深色正文的 `#f5f5f7`
差着三级。上面「已知未做」里那条取舍，说的就是这件事。

### 做法：内联，让 `currentColor` 解析在页面里

- 产物从 `docs/public/` 挪到 `theme/assets/`，由 `theme/utils/flow-art.js` 用 `?raw`
  读成标记串，组件 `v-html` 内联。**不写墨色**，`.pair__shot { color: var(--lp-text) }`
  一句话深浅两套全跟上；只留 `stroke="currentColor"` 交给页面解析。
- `role="img"` + `aria-label` 挂在外层容器上 —— 内联 SVG 没有 `alt`，读屏得靠这个。
- 浮层那边同理；`object-fit: contain` 换成 SVG 自带的
  `preserveAspectRatio="xMidYMid meet"`，本来就是同一个语义。
- **尺寸必须用 `:deep()` 才管得到**（这一条是当天晚些时候才发现的，见文末「后续二」）：
  `v-html` 注入的节点上不带作用域 id，`.pair__shot > svg` 编译出来会要求 svg 自己带
  `data-v-xxx`，整条规则**静默失效**。

### 加号的档位不再采图，也不再问 `isDark`

原先 `sampleTone()` 把底图右下角裁一块扔进 canvas 量亮度 —— 那是给「卡面浅、图深」的
UI 截图用的。现在笔画取的就是主题正文色，+ 压着的那一块本来就几乎没墨，
底下真正的颜色就是卡面底色，而卡面底色只由主题决定。所以直接写进 CSS：

```css
.pair__plus { background: #1d1d1f; color: #f5f5f7 }   /* 浅色卡面：黑圆白加 */
.dark .pair__plus { background: #f5f5f7; color: #1d1d1f }
```

**挂在 `.dark` 上而不是某个 JS 状态上**，是这次实测出来的：先写成
`isDark ? 'dark' : 'light'`，断言时手动切 `<html class="dark">`，
墨色跟着变了、`+` 却留在上一档 —— VitePress 的 `isDark` 与页面上的类不是同一时刻更新。
颜色链上少一个「状态与样式可能不同步」的环节，就没有这个缝。

### 一处必须避开的坑：theme chunk 是每页都加载的

最初写成静态 `import`，构建后量了一下：

| | 静态内联 | 拆成独立 chunk | 对照（原先的 `<img>`） |
|---|---|---|---|
| theme chunk gzip | 47543 | **40546** | 40512 |
| 首页 HTML gzip | 18885 | **12356** | 12358 |
| 图案本身 gzip | 0 | 5824（1 个请求） | 5686（2 个请求） |

静态内联等于让**每一个文档页**都替首页一张装饰多下 7 kB gzip ——
实测 `start.html` 与 `index.html` modulepreload 的是同一个 `theme.*.js`。
改成在 `onMounted` 里 `await import('../utils/flow-art.js')`，Vite 就把它拆成
`flow-art.*.js`：theme chunk 与 HTML 都回到基线，首页只多一个请求，比原先两张 `<img>` 还少一个。

代价是首屏 HTML 里没有图案（SSR 拿不到这个 chunk）：卡片在脚本到位前只有文字。
可接受 —— 这一段在首屏之外，而且图案是绝对定位的装饰、尺寸不参与任何布局，
晚到不会引起位移；图案没到位时 `aria-label` 仍在，读屏照样拿到完整描述。

| 1440×900 深色 | 笔画 `rgb(245,245,247)`，`filter: none`，`+` 白圆黑加 |

## 后续二：`viewBox` 按墨迹裁、文件给出固有尺寸（2026-09-28 稍晚）

需求又来一句：「但是打开后这个 svg 应该是居中的吧？」——附的是把 SVG 单独打开后的截图：
图案上边空一大片、下边几乎贴着图片边沿，看着像被切掉了半截。

量了一下，两件事都成立：

| | 原先的边距（左/上/右/下） | 说明 |
|---|---|---|
| ① 想明白 | **24.8 / 12.8 / 24.8 / 1.8** | 下边只剩 1.8 个单位，图案是「贴底」的 |
| ② 记得住 | **141 / 34.8 / 126.8 / 34.8** | 左右差 14.2，图案偏左 |

原因很直白：`viewBox` 一直是**作者画稿用的那张字符网格**（276×176 / 540×330），
而不是图案本身的范围。网格对「把字摆上去」是必要，对「图片的边框」是多余的。

### 改法

- `bakeAscii` 顺手把**墨迹的包围盒**量出来（按真的落了字的格子并集，字形尺寸查表，
  不去事后解析 `d` 里的相对指令）；`wrapAscii` 用它裁 `viewBox`：
  **四边各留 12 个用户单位**（四条边各自取整，所以最多差 0.5）。
  网格从此只服务于排版，不再兼任图片边框。
- **`width` / `height` 照 viewBox 给**（252×187 / 298×286）。上一轮我把它们删了，
  理由是「内联 SVG 上这两个是表现提示，容易被只覆盖一个轴的 CSS 坑到」——
  属性确实会被 CSS 接管，但**删掉的代价是这份文件没有固有尺寸**：
  单独打开时各家查看器只能自己猜（猜 300×150 的有、猜铺满窗口的有），
  猜出来的长宽比与 viewBox 不一致，图案就被摆歪了。
  现在尺寸由 CSS 的 `:deep(svg) { width: 100%; height: auto }` 整个接管，属性只服务「单独打开」。
- `preserveAspectRatio="xMidYMid meet"` 显式写出来 —— 默认值就是它，
  但「装不下时按比例缩、居中」对这份图是硬要求，写明白是声明意图。

### 顺手挖出来的一个静默失效

改完第一版没生效：卡片里的图**不缩放也不居中**，退回 `width` / `height` 属性的固有尺寸。
原因是 **`v-html` 注入的节点上不带作用域 id**，`.pair__shot > svg` 编译出来是
`.pair__shot[data-v-x] > svg[data-v-x]`，而注入进去的 `svg` 没有 `data-v-x` —— 整条规则
静默失效，什么都不报。之前一直没暴露，是因为那时 SVG 没有固有尺寸、内联 SVG 默认就铺满，
看起来「正好对」。改成 `:deep()` 之后编译成 `.pair__shot[data-v-x] svg`，才真的管上。
（`MermaidDiagram.vue` 里那条 `.ds-diagram :deep(svg)` 是同一件事，仓库里早有先例。）

### CSS 的四个数值是反解出来的

元素框现在 ≈ 图案本身（墨迹 + 一圈 12 个单位的留白），`width` / `right` / `bottom`
的含义从「一张带透明边的画布放在哪儿」变成「图案自己多大、落在哪儿」。
为了不让这一版改动顺手把卡片构图也改了，四个位置的数值是**拿改前墨迹在卡片上的实际矩形
反解**出来的：

| | 改前墨迹矩形（卡片坐标） | 改后 |
|---|---|---|
| 桌面 ① | `[左 55, 上 232, 245 × 175]` | 逐像素一致 |
| 桌面 ② | `[左 268, 上 139, 269 × 258]` | 逐像素一致 |
| 移动 ① | `[左 56, 上 173, 230 × 164]` | 逐像素一致 |
| 移动 ② | `[左 79, 上 151, 193 × 185]` | 逐像素一致 |

`.pair__shot--0` 桌面 `width 84% → 76.6%`、`right 8% → 11.8%`、`bottom 7% → 4.4%`；
`.pair__shot--1` 桌面 `width 75% → 41.4%`、`right 7% → 22.8%`、`bottom 2% → 7%`；
两条移动端规则同样重解（② 那条顺手去掉了 `right: -6%` 的越界裁切 —— 没有透明边了，不需要）。

## 已知未做 / 取舍

- **画面分辨率掉了一个量级**。网点 2px、字符 6 × 11px，格面积是原来的 16 倍多。
  ① 只有 46 × 16 格、② 90 × 30 格，主体的细节（行星的环形山那种）一概装不下 ——
  这是「字要认得出来」的必然代价，`2026-09-18-hero-ascii-dither-design.md` 里
  为 hero 量过同一条（结论是格高低于 10px 字形就糊）。
  所以两张图的主体都只剩「一个符号」，没有第二个层次的细节。
- **① 的问号在 8 行里画**。钩 / 竖 / 点加起来只有 8 格高，笔画宽 9px，
  在这个尺寸上已经是问号能有的最好样子；卡面上读得出来，但谈不上精细。
- **边框左右比上下厚**（1.8 格 vs 1 格）。6 × 11 的格子下，一条等宽描边折过去
  必然如此，除非左右也用 11px（那就变成 2 格，更厚）。选了接受。
- **深色不再靠 `invert(1)`**（当天晚些时候改掉，见文末「后续」一节）。
  改之前：墨色写死近黑，深色图就是它的底片，反相后是 `#e2e2e0` 而不是站点深色正文的
  `#f5f5f7`。现在墨色直接取 `--lp-text`，两套主题都是站点自己的颜色。
- **旧的 `flow-*-dither.svg` 与 `gen-flow-dither.mjs` 已删除**。
  两者都在 git 里，`git checkout HEAD -- <path>` 就能拿回来；
  回退时要把 i18n 里的 `art` 改回 `img` 路径、`StepFlow.vue` 改回 `<img>` 与那几组定位数值
  （都在本文档里记着）。
  `lib/dither.mjs` 这一版只做了加法（`hollow` / `ellipse` / `emit` 的参数），
  旧的生成器拿回来照样能跑。
- **单独打开时按设计尺寸显示**（252×187 / 298×286）。固有尺寸取的就是这个数，
  与 dither 那边「画布即显示宽度」是同一口径；浏览器里打开任何图片都是左上角按原尺寸摆，
  想要铺满窗口得靠查看器自己缩放。给更大的固有尺寸（比如 2 倍）会让「单独打开」好看些，

- **`.sheet__shot` 里的图案比上一轮大约 6%（①）／15%（②）**。浮层的画面区高度是定死的
  （`clamp(180px, 42dvh, 420px)`），图片变「瘦高」之后 `meet` 能用的高度更充分。
  这是把 viewBox 收紧的连带结果，看着是更满了，不是错位。
