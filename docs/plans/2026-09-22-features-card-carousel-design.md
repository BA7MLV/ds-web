# 功能区轮播卡（左文 / 右窗）

日期：2026-09-22
状态：已实现（桌面 / 平板 / 手机 × 亮暗已核对；视觉与动画共返工七轮，逐轮记录在文内）

## 背景

功能区的标题是「四件事，装进同一个窗口。」，但形态是「顶部一排 pill tab + 5fr / 7fr 图文」，
右边一台自绘笔记本（`DeviceFrame.vue`）里换截图 —— 信息是对的，构图不是「一个窗口」。

产品侧给了一张参考图（uberall 的首页分区块）：**一张圆角卡，左半放文案（eyebrow → 大标题 → 描述 → Learn more），
右半一整块深色品牌面，卡下方是圆点 + 左右箭头。** 这次按这个构图重做。

前情见 `2026-09-17-features-device-frame-design.md`（那次解决的是「四张图收进同一台电脑」）。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| 右半深色面里放什么 | 不放 logo（我们没有四个 logo），放**窗口壳 + 截图**浮在深色面上 |
| 导航 | **去掉顶部 pill tab**，只留圆点 + 左右箭头；四个功能名写进左半的 eyebrow |
| 原来的笔记本框 | 不用了。`DeviceFrame.vue` 保留备用，`HomePage.vue` 不再引用 |
| 卡的边界 | **不描边、不投影** —— 靠卡面与页面的**底色差** + 圆角做区分（第一版加过 ring + 投影，第二版试过与页面同白，都退回来了） |
| 切换动画 | **整卡推挤**：新卡滑进来把旧卡顶出去，两张卡贴着、同速、全程不透明（`gap` 恒等于卡宽）。卡片内部（文案滑动、窗口淡入）的动效全部撤掉 |
| 左半文字层级 | **只有三种状态**：小标签 / 标题 / 正文（lead 与 desc 同级，不再分两级） |

第二行决定了原来的 `movePill()`（JS 测量 pill 位置）连同 `t-tabs` 的引用一起从组件里删掉。

## 一、切场景 = 整卡推挤

动画改了三轮，最终定在「推挤」：**新卡从一侧滑进来，把旧卡顶出去**，两张卡贴着、同速走、全程不透明。

前两轮分别是「卡片不动、只换屏里的画面」（文案滑进滑出 + 窗口原地淡入淡出）和「整卡各自飞出飞入」
（旧卡一边往左飞一边淡掉、新卡同时从右边飞入）。后者的问题出在**淡出**：两张卡互相溶解，
读起来是「换掉了」而不是「推走了」—— 要的正是后面那种手感。

推挤由 `<Transition name="fcard">` 实现，`:key="displayedScene"` 一变就同时启动两张卡的位移。

**用默认的「同时」模式，不用 `out-in`**：`out-in` 期间容器里一张卡都没有，`.lp-fstage` 的高度会塌成 0，
下面那一整段内容会被顶上再落回。同时模式则始终有一张卡撑着高度。

### 推起来要同时满足的条件

| 条件 | 做法 | 破了会怎样 |
|---|---|---|
| 位移是**整卡宽** | 入场 `+100% → 0`、出场 `0 → −100%`（百分比相对卡宽） | 只用几十像素的「飞一下」，两张卡中途就分开露缝了 |
| 进出场**同曲线、同时长** | 两个 active 类共用 `--fc-dur` / `--fc-ease` | 「出场快、进场慢」看着更生动，但两卡会走散：一边空出一截、另一边还没跟上 |
| 不要 `opacity` | 两张卡全程 1.00 | 一加淡出就退回「淡出淡入」，推挤感立刻消失 |
| 容器宽 = 卡宽 | `.lp-fstage` 不加左右留白 | 两边多留一点，旧卡收尾时会在边上剩一条没走完的窄边 |
| 离开的那张 `absolute` | `.fcard-leave-active { position: absolute; inset: 0 }` | 两张卡在文档流里上下排开，容器高度瞬间翻倍、下面整段内容被顶下去 |
| 方向取正负 | `.lp-fstage` 上写 `--fc-dir`（1 / −1），CSS 用 `calc()` | 否则「下一个 / 上一个」要写四组类名 |

### 实测：接缝恒为 0

判据是两张卡的间距 `gap = 新卡 tx − 旧卡 tx` —— 推挤成立时它应该**恒等于卡宽**（1440 宽下 1080px）：

| 时刻 | 旧卡（资料对话） | 新卡（知识导图） | gap | 分段位移 |
|---|---|---|---|---|
| 0 | 0px / 1.00 | — | — | — |
| 120ms | −67px / 1.00 | +1013px / 1.00 | 1080 | 67px |
| 240ms | −230px / 1.00 | +850px / 1.00 | 1080 | 163px |
| 360ms | −487px / 1.00 | +593px / 1.00 | 1080 | 257px |
| 480ms | −703px / 1.00 | +377px / 1.00 | 1080 | 216px |
| 600ms | −870px / 1.00 | +210px / 1.00 | 1080 | 167px |
| 720ms | −959px / 1.00 | +121px / 1.00 | 1080 | 89px |
| 840ms | −1016px / 1.00 | +64px / 1.00 | 1080 | 57px |
| 1200ms | 已移除 | 0px / 1.00 | — | — |

`gap` 全程 1080、`opacity` 全程 1.00、容器高度全程 401px —— 三件事同时成立，才叫「贴着推」。

### 曲线：先削掉尖峰，再谈「慢」

`--fc-dur: 1200ms`、`--fc-ease: cubic-bezier(0.35, 0.35, 0.25, 1)`。

一整卡宽（1080px）的位移里，**总时长不是唯一变量，速率分布才是**。上一版用 iOS 那条
`cubic-bezier(0.32, 0.72, 0, 1)` / 780ms，把 55% 的位移堆在 120–360ms：

| | 780ms + iOS 曲线 | 1200ms + 现在这条 |
|---|---|---|
| 峰值速率 | 3508px/s | **2142px/s** |
| 峰值 / 平均 | 3.9× | 2.4× |
| 速率形状 | 尖峰（前 1/3 走掉一半多） | 钟形（558 → 2142 → 475 …） |

只把时长拉到 1200ms、曲线不动，峰值仍有 3508px/s —— 尾巴拉长了，尖峰还在，读起来照样是「嗖」。
换成现在这条平缓曲线（起点斜率仍是 1，点了立刻动；中段不冲；末端照样缓停）之后，
速率摊成钟形，整体才真的慢下来。

**测速别只看总时长**：按 120ms 采样 `tx`，相邻两点差值除以 120ms 才是人眼感知到的那个数。

**这一版没用过冲**（更早一版为了让非线性更显眼，给进场加过弹簧过冲，卡片会飞过落点约 10px 再弹回）。
推挤里必须撤掉：两张卡共用一条带过冲的曲线，回弹时会一起反向走 —— 接缝虽然还是 0，
但整块会「倒退」一下，读起来像页面在抖。当时为过冲准备的跑道（`.lp-fstage` 的 16px 左右留白）也一起撤了。

> 一句话记：推挤的判据不是「两张卡都在动」，而是**接缝不变**。位移量、时长、曲线、方向，
> 任何一项两张卡对不上，它就退化成「两张卡各飞各的」。

## 二、两列等宽，卡高交给网格

```css
.lp-fcard { grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); }
.lp-win   { width: min(100%, 460px); }
.lp-win__screen { aspect-ratio: 16 / 10; }
```

窗口宽度按右列宽度取百分比、高度由 16:10 推出，**网格行高自动取左右两者的较大值** ——
所以「文案变短 → 窗口顶出卡片」这种溢出不会发生，也不需要给右列写 `min-height`。

实测桌面 1440 下卡高 401px（参考图 410px）、窗口 452 × 313（含 30px 标题栏）。

## 三、左半只有三种文字状态

左半的四行字（小标签 / 标题 / 主张 / 细节）如果各给一套字号色阶，读起来是**四种状态**，
层级比内容本身还多。现在收成三种：

| 状态 | 元素 | 字号 | 颜色 |
|---|---|---|---|
| 小标签 | `.lp-fcard__eyebrow` | 13px / 500 | `--lp-text-2` |
| 标题 | `.lp-fcard__title` | `clamp(1.625rem, 3.2vw, 2.375rem)` / 600 | `--lp-text` |
| 正文 | `.lp-fcard__lead` + `.lp-fcard__desc` | 1rem / 1.7 | `--lp-text-2` |

关键在最后一行：`lead`（主张）与 `desc`（细节）**共用一条规则**，只靠段间距（0.6rem）分开。
第一版给 `desc` 降到 15px + `--lp-text-3`，左半就同时出现了四种字色 —— 明细比主张更淡
在长文档里成立（`.lp-col__desc` 那套仍在），但这里只有两行，退一级只会读成「排版没对齐」。

## 四、圆点就是 tab

参考图底下那排圆点是**控件**，不是装饰，所以无障碍语义原样保留：

- 圆点容器 `role="tablist"` + `aria-label`（沿用 `home.features.tabsLabel`）
- 每个圆点 `role="tab"` + `id="scene-tab-{i}"` + `aria-controls="scene-panel"` + `aria-selected`
- 卡片 `role="tabpanel"` + `aria-labelledby="scene-tab-{activeScene}"`

与上一版的差别只在控件形态（文字胶囊 → 点）。圆点没有可见文字，所以每个点用
`home.features.dot`（`第 {index} 个场景：{name}`）补 `aria-label`。

两个度量：

| 项 | 值 | 为什么 |
|---|---|---|
| 圆点 / 间距 | 9px / `gap: 16px` | 中心距 25px，与参考图一致 |
| 命中区 | `::after { inset: -8px }` | 视觉仍是 9px 的点，手指点得到 25px 见方 |

## 五、窗口壳跟着截图走，不做暗色版

屏里永远是**浅色截图**，所以窗口壳（标题栏 + 交通灯）两套主题都用浅色：
否则暗色下会出现「深色标题栏 + 浅色屏幕」的割裂感。交通灯沿用 `AppShell.vue` 的三个色值，
只是小一号（9px / `gap: 6px`）。

标题栏里放当前场景名。要让它**真居中**，右侧得补 `margin-right: 39px`
（= 3 × 9 + 2 × 6，左边三盏灯占掉的宽度），否则文字会向右偏 20px —— 这是最容易漏的一处。

## 六、亮暗两套的三个面

| 变量 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--fc-face` | `--lp-tile` = `#f5f5f7` | `#2e2e33` | 卡面（左半）。亮色下与白页面拉一档；暗色下比页面（`#1b1b1f`）亮 19 级才站得住，见下节 |
| `--fc-dark` | `#131316` | `#0e0e10` | 右半深色品牌面。两套都是「比卡面更深」，主题切换时这块面的性格不变 |
| `--fc-arrow-bg` | `#efeff1` | `rgba(255,255,255,.1)` | 箭头圆底 |

深色面上还叠了一道很淡的径向光（`radial-gradient` 写在 `.lp-fcard__stage` 上），
纯色面在暗色下会显得是一块死色。

### 关于「卡的边界」（返工两次）

**第一版**：给卡片加了 `inset 0 0 0 1px` 的 ring + 一层投影，怕亮色下「白卡落在白底上分不出来」。
实机看：那圈 ring 就是一条边框，投影是多余的重量 —— 两个都去掉了。

**第二版**：去掉之后让卡面与页面**同白**（`#ffffff`）。结论是不行 ——
亮色下整张卡只剩右半那块深色面，左半的文字像直接浮在页面上，卡片读不出来。

**最终做法：用底色差**。卡面取 `--lp-tile`（亮色 `#f5f5f7`），与白页面拉开一档；
顺带让功能区这张卡与「使用流程」的两张卡（`.pair__card` 也是 `--lp-tile`）、页脚卡片成了同一个面 ——
同一页上的「卡」应该是同一个颜色，这一条比「和白底一样干净」重要。

暗色下要**再亮一档**（`#2e2e33`）：页面 `#1b1b1f` 与 `--lp-tile` `#26262a` 只差 11 级，
暗部人眼对这点差异不敏感，卡会糊回背景里去（实测截图确认过），
所以 `.dark` 里 `--fc-face` 单独给了值，不跟随 `--lp-tile`。

顺带一句：窗口壳自己的投影留着，但它落在近黑的深色面上，实际几乎看不出来 ——
留着是为了将来把深色面调浅时不至于让窗口「贴」在上面。

## 七、顺手清掉的死代码

>
> 另一个：`evalJs` 里别只写 `click()` 忘了 `scrollIntoView` —— 会截到页面顶部（Hero），
> 看着像「切场景把页面弹回去了」。
>
> 第三个（这次最耗时间）：CDP 实例跑久了会「坏」。症状有递进 —— 先截到一张
> `ERR_CONNECTION_REFUSED` 的图（但同一轮的 `evalJs` 明明读到了正确 DOM），再下一轮 `evalJs`

> 第四个：**抓动画中间帧不能靠「等 N ms 再截图」。** `shot.mjs` 在 `evalJs` 返回后还要等 `settleMs`
> 才截，再加上 CDP 往返，标称 130ms 的那一帧实际落在 280ms 之后 —— 抓到的永远是接近落定的画面
> （第一次抓帧就被这个骗了，以为动画没跑）。正确做法是在页面里把动画**冻住**再截：
> `document.getAnimations().forEach((a) => a.pause())`，同时把 `settleMs` 传 0。
> 只要**数值**不要图时更简单：逐 70ms 读 `getComputedStyle(card).transform` 矩阵的第五位 ——
> 比看图准，也更快暴露「位移根本没动」这类问题。

## 可调参数

- 卡：`.lp-fcard` 的 `grid-template-columns`（想左窄右宽就改 `5fr / 7fr`）、`border-radius: 20px`
- 动画：`--fc-dur`（1200ms）与 `--fc-ease`（`cubic-bezier(0.35, 0.35, 0.25, 1)`）**两张卡共用**，
  改就一起改；位移量写在 `.fcard-enter-from` / `.fcard-leave-to` 的 `100%` 上（相对卡宽，一般不用动）。
  **改完必须采样两件事**：① `gap`（= 新卡 tx − 旧卡 tx）得恒等于卡宽，掉下来就说明两张卡走散了；
  ② 分段速率（每 120ms 的位移增量 ÷ 120），峰值别超过平均的 2.5 倍，否则又会「嗖」
- 容器：`.lp-fstage` 的宽度必须等于卡片宽度（现在靠「不加左右留白」保证）；
  一旦给它加 padding 或负 margin，百分比位移就会失配，旧卡收尾会留窄边
- 窗口：`.lp-win` 的 `width: min(100%, 460px)`（想更大就抬上限）；比例在 `.lp-win__screen` 的
  `aspect-ratio: 16 / 10`（换非 16:10 素材时同步改）
- 圆点：`.lp-fdots` 的 `gap`（改完记得同步 `::after` 的 `inset`，命中区别互相压）
- 箭头：`.lp-farrow` 的 `36px` 直径（520px 下改 32px）
- 文案：全部在 `theme/i18n/messages/<lang>.js` 的 `home.features`
