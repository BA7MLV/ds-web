# 功能区四扇「窗口屏」：截图换成有序抖动图案

日期：2026-09-26
状态：已实现（桌面亮/暗 + 移动端已核对）

## 需求

> 「资料学习与智能对话 / 知识导图 / 题目集与练习 / Anki 智能制卡，这里的图片我也想要
> Dithering 效果的图案。类似这里的一样：想明白 · 围绕你的材料对话 / 记得住 · 变成能复习的东西。」

指的是 `HomePage.vue` 功能区轮播卡右半那扇窗（`.lp-win__screen` 里的 `.lp-shot`）。
四张真截图（`/home-chat.png`、`/home-mindmap.png`、`/home-quiz.png`、`/home-anki.png`）
换成与各自文案相关、和「使用流程」两张卡同一种笔法的抖动图案。

前情：`2026-09-25-flow-dither-scifi-design.md`（那一套的口径与全部踩坑记录）。

## 不变量（与「使用流程」那两张必须逐条一致）

1. **同一套阈值化管线**：灰度场 → Bayer 8×8 → `(b + 0.5) / 64` 阈值 → 1-bit 网点。
2. **同一个网屏**：`CELL = 2`，一个网点 2 CSS px（DPR 2 上落在 4 个物理像素）。
3. **同一支笔法**：形状用解析几何现画、按格 SS×SS 超采样求覆盖率，边是干净的收口，不是锯齿。
4. **产物是静态 SVG**，运行时只有一张 `<img>` —— 不给首页加 canvas 与渲染循环。
5. **最重一档 ≤ 0.86**：0.9 以上阈值化出来是一块实心墨，与细网点不是一路。

## 与「使用流程」那两张的三处不同

| | 使用流程（`.pair__shot`） | 功能区（`.lp-win__screen`） |
|---|---|---|
| 画布 | 280×176 / 544×340 | 452×282（四张同尺寸） |
| 溶解边 | 只做左边与顶边（右边、底边被卡片裁掉，要留硬边） | **四边都做** —— 硬边界交给窗口壳 |
| 墨色 | 近黑 `#1d1d1f`，深色下靠 `filter: invert(1)` | 浅色 `#e8e8ea`，**不反相** |

第三行是关键，而且必须先纠正一个过时的事实。

### 「屏里永远是浅色截图」这句已经不对了

`2026-09-22-features-card-carousel-design.md` 第五节写着「屏里永远是**浅色截图**，
所以窗口壳两套主题都用浅色」。但把四张图的主色采样出来（`scripts/` 外的一次性脚本，
逐 7 像素统计）：

| 图 | 尺寸 | 出现最多的颜色 |
|---|---|---|
| `home-chat.png` | 2400×1502 | `rgb(31,32,33)` |
| `home-mindmap.png` | 2400×1500 | `rgb(31,32,33)` |
| `home-quiz.png` | 2400×1500 | `rgb(31,32,33)` |
| `home-anki.png` | 2400×1500 | `rgb(31,32,33)` |

四张全是**深色**界面，底色 `#1f2021`。老文档那句是错的（截图后来被换成深色的了）。
窗口壳保持浅色标题栏这个结论仍然成立 —— 那是 macOS 的「浅色 chrome + 深色内容」，
但理由不是「截图是浅的」。

这一条直接决定了图案的墨色方向：**深底压白墨**，而不是像「使用流程」那样白底压黑墨。
反过来做的话，右半那扇窗会从「深色窗口」变成一块发亮的白板，
与卡片、与整页的重量分配都对不上。

所以：

- `.lp-win__screen` 的 `background` 由 `#ffffff` 改成 `#1f2021`（从四张截图里采出来的那个值），
  并升成变量 `--fc-screen`。
- 图案的墨色写死 `#e8e8ea`（比站点深色正文 `--lp-text` `#f5f5f7` 低一档，
  与「使用流程」图案反相后的 `#e2e2e0` 是同一档重量）。
- 组件里**不需要**按 `isDark` 挑 `src`，也**不需要** `filter: invert()` —— 两套主题下这扇窗
  本来就是同一张深色屏。这一条比「使用流程」那两张还省事。

## 画布尺寸是量出来的，不是估的

无头 Chrome 1440×900、DPR 2 实测（`#features` 处）：

```
.lp-wrap        1080px
.lp-fcard       1080px    两列各 540px
.lp-fcard__stage 内边距  44px（clamp(1.75rem, 3.4vw, 2.75rem) 在 1440 下取上限）
.lp-win          452 × 312.5   （width: min(100%, 460px)，右列内宽 452 说了算）
.lp-win__screen  452 × 282.5   （aspect-ratio: 16/10）
```

取 **452 × 282**（226 × 141 格）。1px 就是 1px，网点在 DPR 2 的屏上是硬边的。

### 屏幕比例必须照资产取，不能用 16:10

这一条是**像素级量出来才发现**的，光看元素尺寸看不出来。

`.lp-win__screen` 原本写的是 `aspect-ratio: 16 / 10`（照旧截图 2400×1500）。但 452 宽的盒子
按 16/10 算出来是 **282.5** 高，而画布是 282 —— 0.18% 的纵向拉伸。量法是：
图案的每个网点边界都写在 `CELL = 2` 的整数倍上，1:1 渲染时设备像素里的每一次明暗跳变
都必须落在 4 的整数倍上（DPR 2）。一旦被缩放，跳变位置就会散开。

| | 屏盒子 | 横向跳变落在 4 的倍数上 | 纵向 |
|---|---|---|---|
| `aspect-ratio: 16 / 10` | 452 × 282.5 | 22970 / 22970（100%） | 20076 / 23352（**86%**） |
| `aspect-ratio: 452 / 282` | 452 × 282 | 22416 / 22416（100%） | 23352 / 23352（100%） |

横向一直是准的（宽度就是 452，没有余数），问题只在纵向。
改成 `452 / 282` 之后两个方向都严格落在网格上 —— 纵向那一列全落在 `y % 4 === 3`，
是元素在页面里的固定亚像素位置（`y = 2070.42`）带来的**纯平移**，不是缩放，无害。

**换回截图素材时，这个比例要跟着换成素材的实际比例。**

### 已知的缩放：窗口宽度是浮动的（实测）

`.lp-win` 是 `min(100%, 460px)`，100% 那一支是右列内宽，跟着视口走。
逐档量了一遍（DPR 2，只量 `.lp-shot` 的计算宽度）：

| 视口 | `.lp-wrap` | 右列 | 窗口 | 相对画布 |
|---|---|---|---|---|
| 1440 | 1080 | 540 | **452** | 1.000（基准） |
| 1128 | 1080 | 540 | 452 | 1.000 |
| 1012 | 964 | 482 | 413.2 | 0.914 |
| **901** | 853 | 426.5 | **365.25** | **0.808（桌面最窄）** |
| 900（塌单列） | 852 | 852 | 460 | 1.018 |
| 390（移动端） | 342 | 342 | 302 | **0.668（全局最窄）** |

所以「1:1」只在 1128px 以上成立。最坏两档是 901px 的 0.808 与 390px 的 0.668，
网点会软一档，但形状与层次都还读得出来（`plans/features-dither/shots/` 里有这两档的截图）。

这与「使用流程」那两张是同一个取舍（它们的宽度也是百分比）。要做到任何视口都 1:1，
只能把窗口宽度钉死成固定 px，那会牺牲现在的响应式 —— 这一版照旧接受。

## 四张图案各自说什么

每张只讲**一件事**，题眼是那一件事里最不可替代的那个物件。
四张都用同一种笔法：主体落在 0.5–0.86，陪衬压在 0.5 以下，让网点自己分出前后。

| # | 文案（title / lead） | 画面 | 题眼 |
|---|---|---|---|
| ① | 资料学习与智能对话<br>围绕你自己的材料学习 | 左边一页材料（七行正文，其中一行被压成实心高亮条），右边一个对话气泡；一根引线从气泡尾巴连到高亮条右端，末端钉一个小圆点 | 那根**引线** —— 「引用面板直接调取你的资料」：答案指着材料里的某一段 |
| ② | 知识导图<br>把知识整理成结构 | 正中一个根节点胶囊，上下左右四个一级节点，左右一级节点再各挂两个更小更淡的二级节点，连线是 2.5px 的胶囊 | **层级** —— 根最重、一级中等、二级最淡，三级明度差就是「结构」本身 |
| ③ | 题目集与练习<br>把教材、试卷变成可练习的题库 | 左边一张卷子（页眉线 + 两道题：题号块、题干线、三个选项圆点，其中一个是实心选中的），右上角一个圆环勾徽章，右下角一条掌握度条 | **勾徽章 + 掌握度条** —— 「自动判分，掌握度按知识点追踪」 |
| ④ | Anki 智能制卡<br>把理解变成长期记忆 | 上中三张错开的卡片（前排那张有两长一短三条线），下方一条**衰减锯齿曲线**：三次下坠、三次被复习拉回 | 那条**曲线** —— 「长期记忆」的遗忘曲线。全页只有这一处出现曲线，辨识度靠它 |

② 的明度阶梯、③ 的勾、④ 的曲线，都是「换一张图就说不通」的东西 ——
这一条是判断构图有没有偷懒的标准。

## 两个新图元

### `polyline`（④ 的曲线要用）

把一串点连成一条等粗的折线，每段都是一根胶囊（所以拐点是圆的）。
不用「逐段调 `seg` 画上去」的写法：相邻两段会在拐点重叠，
`paint` 的混合式 `field = field*(1-cov) + tone*cov` 虽然幂等（同色重叠不出错），
但每个点都要跑一遍包围盒裁剪，白白多算。

### `rampEdges`（四边溶解）

原来 `gen-flow-dither.mjs` 里的 `rampAt` 把「左边 + 顶边」写死了。
抽成按边给缓坡宽度的工厂：

```js
rampEdges({ left: 0.1, top: 0.11 })              // 使用流程：原样，产出逐字节不变
rampEdges({ left: 0.066, right: 0.066, top: 0.106, bottom: 0.106 })  // 功能区：四边
```

缓坡宽度按**边长的比例**给，两张画布尺寸不同，所以比例也不同 ——
0.066 × 452 与 0.106 × 282 都约等于 30px，四边化掉的范围一样宽。

## 顺手做的一件事：把图元抽成 `scripts/lib/dither.mjs`

`gen-flow-dither.mjs` 的文件头注释里写着「这个文件同时是一份可复用的库」，
还引着一个已经不存在的消费者（`plans/flow-dither/gen-variants.mjs`）。
这一版真的要第二个消费者了，于是把图元抽到 `scripts/lib/dither.mjs`
（与 `scripts/lib/` 下已有的 `demo-mirror.mjs`、`release-downloads.mjs` 同级），
两个生成器各留自己的构图与写盘。

**验证方式**：抽完之后 `node scripts/gen-flow-dither.mjs` 产出的两个 SVG
必须与抽之前 **sha256 逐字节相同** —— 重构没改行为，这一条能直接证明。
（`rampEdges({left: 0.1, top: 0.11})` 与原来的 `smoothstep(0,0.1,u) * smoothstep(0,0.11,v)`
在 IEEE754 下同序同值，所以是恒等的。）

## 关于「要不要去掉窗口壳」——结论是保留

做完之后问过一句「要不要去掉这个壳层」。结论：**保留**，理由只有一条是决定性的：

**功能区的区块标题就是「四件事，装进同一个窗口。」**（en: "Four tools, one window."），
而 `2026-09-22-features-card-carousel-design.md` 里那台窗口壳就是为了让这句话成立才做的
（原文：「信息是对的，构图不是『一个窗口』」）。去掉壳层等于把那次返工重新推翻：
标题在说「窗口」，读者看到的却是一块没有边界的深色面板。

另外两条次要理由：

- **标题栏是「同一个窗口」唯一的可见证据**。四个场景切换时，换的是窗口里的东西、
  窗口本身不动 —— 这一条靠标题栏文案（资料对话 → 知识导图 → …）才看得见。
  去掉之后切场景就只是「换了一张图」。
- **两个区块会长得一样**。「使用流程」两张卡是「图案直接长在卡面上」，
  功能区如果也这样，同一页上就是同一种构图出现两次；壳层把这一节与那一节分开了。

去掉壳层的版本也渲过（`plans/features-dither/shots/ab-no-shell.png`）：单看这一节确实更干净、
图案也更舒展，但它换来的是标题落空。**如果将来标题改成不带「窗口」的说法，这个决定就该重判。**

## 已知未做 / 取舍

- **四张截图没删**。`/home-*.png`（合计 1.78 MB）现在没人引用了，与上一版「使用流程」的处理一致：
  确认不回头之后再一起删。
- **窗口宽度浮动会带来轻微缩放**（见上）。要做到任何视口都 1:1，只能把窗口宽度钉死成
  固定 px，那会牺牲现在的响应式。移动端 0.668 倍是这套方案里最软的一档。
- **图案不表达产品界面**。它只表达「这个功能在干什么」。
  想看真界面的人走「了解更多 ›」进文档 —— 那条链接本来就在。
- **`--fc-screen` 只有一套值**。两套主题下这扇窗都是深色屏，
  所以不需要 `.dark` 覆盖；将来如果真要做浅色屏，得连图案一起出第二套墨色。
- **四边溶解的宽度是可调的**（`gen-features-dither.mjs` 里的 `rampEdges`，现在四边各约 30px）。
  嫌窗口里「空」的话，把它收到 0.045 / 0.072（约 20px）图案就更满，代价是边缘收口更硬。
