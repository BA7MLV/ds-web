# Hero 星空底图（ordered dithering starfield）

日期：2026-09-16
状态：已实现（待实机确认节奏参数）；**滚动编排与密度场已于 2026-09-17 修订、
按 Hero 底边裁剪已于 2026-09-18 修订，均见文末**

## 目标

给首页 Hero 加一层会闪烁的星空底图，并随滚动完成「漂移到居中 → 下滑出画面并变暗」
的编排；亮暗两种主题下都要成立。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| 滚动编排 | 固定底层 + 滚动进度驱动位移（不是把图挂在 Hero 里跟着滚） |
| 白天模式 | 明暗反转：暗色 = 深空底 + 浅色星点；亮色 = 极浅底 + 深色星点 |
| 抖动实现 | Canvas 2D + Bayer 8×8 有序抖动，无新依赖 |
| 覆盖范围 | 铺满整屏，包括顶栏区域（在顶栏玻璃之下） |

## 分层

```
.SNav（z-index: 30，液态玻璃）        ← 最上，透过玻璃能看到身后的星点
.home-apple（position: relative; z-index: 2）  ← 首页全部内容
.sf（position: fixed; z-index: 1）    ← 星空层，pointer-events: none
页面底色（body / --vp-c-bg）           ← 最下
```

`.sf` 必须挂在 `.home-apple` **之外**（所以 `HomePage.vue` 是多根模板）：
否则 `.home-apple` 自身的 z-index 会让内部的 fixed 层变成「正 z-index 子元素」，
反过来盖住同级的静态内容。`.sf` 用 z-index: 1 而不是 0/负值，是因为任何定位元素
都会画在静态内容之上，必须靠 `.home-apple` 的 z-index: 2 把它压回去。

## Canvas 渲染

- 画布 backing store 按 `SCALE = 0.5`（每 CSS 像素半个离屏像素，宽度上限 960px）渲染，
  CSS 用 `image-rendering: pixelated` 放大回全屏 —— 硬边网点质感，同时把逐像素开销压到
  约 1/4。
- 每帧两步：
  1. 把每颗星写成一段亮度场（限定在自身包围盒内叠加的抛物光斑），开销只跟星点数量成正比；
  2. 用 Bayer 8×8 阈值把亮度场阈值化成 1-bit，只写 alpha 通道（RGB 在主题变化时写一次）。
- 星点密度按 **CSS 面积** 计算（约 1/5200），12% 的「亮星」半径更大。
- 闪烁：每颗星有独立相位与角速度，亮度场起伏 → 同一点阈值判定翻转 → 网点忽密忽疏。
- 密度掩膜：四周软收边（星空不是硬边矩形）+ 中间压一档，避免网点和大标题互相干扰。
- 帧率 30fps（闪烁不需要 60）；`visibilitychange` 隐藏时暂停。

## 滚动编排

`--sf-y` / `--sf-dim` 由 JS 写死在元素上，CSS 只负责插值：

| 进度 p | 位置 | 淡出 |
|---|---|---|
| 0 | 上移 18vh（压在 Hero 偏上） | 无 |
| 0.5 | 0（视口正中，居中） | 0 |
| 1 | 0（原地不动） | 1（画布完全透明） |

进度基准是 Hero section 的高度（`-rect.top / offsetHeight`）。

> **原文此处写的是「所以星空正好在 Hero 滚完时淡尽，不会盖到后面的 `使用流程` 区块」。
> 2026-09-18 实测证伪**：淡出基准是 Hero 的高度，可 Hero 才滚到一半，`使用流程`
> 就已经露出小半屏了 —— 而那时正是星空最亮的时候（p = 0.5，dim = 0）。实测侵入窗口
> 约 685px 的滚动距离。修法与数据见文末「2026-09-18 修订」。

层间视差（`PARALLAX_VH`）仍按星的深度错开，是滚动时唯一的位移来源。

## 降级与边界

- `prefers-reduced-motion: reduce`：不闪烁、不随滚动位移，改成 `position: absolute`
  随文档滚走的一层静态星空（fixed 会一直盖在整页上，不能用）。
- SSR：首屏 HTML 保持确定性，`onMounted` 后才建画布；首帧画完前 opacity: 0，与 Hero
  交错入场一起淡入。
- 卸载：清掉 rAF、scroll/resize 监听、ResizeObserver，路由离开首页即停止。
- 图片素材：无。全部运行时生成，不新增静态资源。

## 可调参数（都在 `HeroStarfield.vue` 顶部）

`SCALE` / `STAR_PER_PX` / `FPS` / `Y_START` / `Y_END` / `CENTER_AT` /
`INK_ALPHA_DARK` / `INK_ALPHA_LIGHT` / `VIGNETTE_LIGHT`，以及 `buildMask` 里的
收边与中间压暗系数。想让深色也有一点印刷质感，把 `vignette()` 的深色分支从 `0`
换成一个很小的值（0.02～0.03）即可，但要注意边界会重新出现。

## 2026-09-17 修订

起因：深色下 Hero 的滚动看着很怪，像「背景还压了一层黑」。逐层量过之后确认
星空层本身没有第二层底色 —— 画布是透明的，退场幕布用的就是页面底色；
在同一次页面加载内开/关整个 `.sf` 层做逐像素比对，滚动到 p=0.75 / 0.95 时
**没有任何一个像素被压暗**。真正的问题在别处：

1. **深色下关掉密度场（`VIGNETTE_DARK = 0` → `buildField(amp = 0)` 返回全零场）。**
   那圈外圈网点在亮色下是「暗点压白底」，中间留着干净的一块；同样的「外圈密、
   中间空」到深色就变成「亮点压近黑底」——那圈点阵的内边界成了一条看得见的轮廓，
   整片读起来就是「背景上压了一层黑」。而它完全不随滚动走，和滚动的星点叠在一起，
   视差一上来特别怪。这正是 2026-09-17 那份打磨文档里已经得出的结论
   （「有序抖动会把任何有边界的亮度场阈值化成一块看得见轮廓的网点云」），
   后来把密度场改成深浅共用时又把它带回了深色。
   深色的厚度改由星点本身表达（远近 / 大小 / 亮度 / 视差）。亮色的暗角公式一字未动。
2. **退场改成原地淡出。** 原来是后半程向下推 118vh 并放大到 1.12 倍；pixelated 画布
   被非整数倍放大 = 网点变糊 + 摩尔纹，深色下星点对比度高，整片像被往下拽走。
   现在 `Y_END = 0`，缩放置 1（`--sf-scale`、`SCALE_CENTER`、`SCALE_END` 已删除），
   画布 `opacity` 直接跟 `--sf-dim` 走，p=1 时淡尽。
3. **删掉 `.sf__veil`。** 它和页面底色等色，从来没改过页面的明暗，唯一作用是盖星点；
   画布改成淡到全透明就够了，少一层「背景色」也少一份误会。

复查方式：1440×900 无头 Chrome 抓 p=0 / 0.5 / 0.75 / 0.95 四帧，断言
`--sf-y` 在 p ≥ 0.5 之后恒为 `0.00vh`、画布 opacity 随 `--sf-dim` 递减到 0.098（p=0.95），
并确认深色背景里不存在覆盖率恒为 0 的椭圆区域。

顺带记两处不一致，**未改动**，留给后续决定：

- `STAR_PER_PX = 1/12000`（1440×1062 的层约 127 颗），而 2026-09-17 那份文档里
  暗色标的是 1/5200（≈294 颗）、`MIN_STARS` 90、墨色不透明度 0.92。代码是更新的
  决定（深浅共用一套），文档未同步。
- `.dark .sh { --sh-window-bg: hsl(0 0% 9%) }` = `#171717`，比页面底色 `#1b1b1f` 更黑；
  亮色下窗壳与页面都是 `#fff`，所以「窗壳比页面更黑」只在深色出现。

## 2026-09-18 修订：按 Hero 底边裁掉星空

起因：星空会透进紧跟 Hero 之后的 `使用流程`（收进来 / 想明白 / 记得住）区块。
`.flow` 自身没有背景色，而 `.sf` 是 `position: fixed` 铺满视口的，所以整片星点直接
压在流程区块下面。

### 先量清楚侵入窗口

视口 813 / Hero 1243 / 流程 2439（1440 宽实测）。淡出进度以 Hero 高度为基准：

| scrollY | Hero 底边 | 流程露出视口 | `--sf-dim` | 星空不透明度 |
|---|---|---|---|---|
| 0 | 1243 | 0% | 0 | 1.00 |
| 400 | 843 | 0% | 0 | 1.00 |
| 500 | 743 | 9% | 0 | 1.00 |
| 700 | 543 | 33% | 0.0013 | 1.00 |
| 900 | 343 | 58% | 0.266 | 0.73 |
| 1100 | 143 | 82% | 0.875 | 0.13 |
| 1179 | 0 | 100% | 1.0 | 0.00 |

Hero 底边在 `scrollY ≈ 494` 触到视口底，而星空要到 `scrollY ≈ 1179` 才淡尽 ——
中间约 **685px 的滚动距离里，流程区块是露着的、星空是亮的**。所以「只靠淡出」
挡不住，必须裁剪。

### 决策

**跟随 Hero 裁剪**：Hero 滚出多少，星空就被裁掉多少。流程区块里一个星点都不会有。

### 实现

- `updateProgress()` 里多算两个量，写到元素上：
  - `--sf-cut`：元素自身坐标系下要裁掉的高度
    `cut = max(0, (y/100)·vh + SF_HEIGHT_VH·vh − limit)`，其中
    `limit = min(vh, max(0, heroBottom))`。
  - `--sf-fade`：软边宽度 `min(cut, SF_EDGE_FADE)`，`SF_EDGE_FADE = 110`。
- `.sf` 加 `clip-path: inset(0 0 var(--sf-cut, 0px) 0)`。
- `.sf__fade` 是 `.sf` 的子元素，用页面底色 `--vp-c-bg` 做一段
  `transparent → 底色` 的渐变盖在星点上，位置跟着 `--sf-cut` 走。

`SF_HEIGHT_VH` 必须和 `<style>` 里 `.sf` 的 `height: 118vh` 保持一致 —— 上面那个
公式要用到它。两处写死同一个数是个隐患，改高度时别忘了。

### 为什么不用 mask

`mask-image` 一处就能同时表达硬边界和渐变收尾，本来是更合适的选择。但**实测它在
无头软件渲染下完全不生效**（截图与基线逐字节相同，加不加 `--disable-gpu` 都一样）
—— 验证不了的效果不留。于是拆成「`clip-path` 管硬边界 + `.sf__fade` 管软边」。

### 软边底边要多探 2px

第一版把 `.sf__fade` 的 `bottom` 直接设成 `var(--sf-cut)`，实测在切口最底那一行
**完全没被盖住**：该行软边/硬边墨量完全相同（2.2569），等于在渐变末尾又留了一行硬边
—— 正是这一层要消掉的东西。

原因是渐变的底边和 `clip-path` 的边界各自由浏览器取整，差出约 1px。改成
`bottom: calc(var(--sf-cut, 0px) - 2px)`，让**边界由 clip 单方面决定**：多铺的 2px
会被 clip 裁掉（`.sf__fade` 是 `.sf` 的子元素，受同一个 `clip-path` 约束），没有副作用。

### 验证

量「软边墨量 ÷ 硬边墨量」的逐行衰减比，与线性渐变的理论值对照
（固定随机种子 + 钉死 `performance.now`，保证两次截图是同一片星空）：

| 行 | 渐变 alpha | 理论残留 | 实测残留（亮色） |
|---|---|---|---|
| 432 | 0 | 100.0% | 100.0% |
| 480 | 0.414 | 58.6% | 58.5% |
| 504 | 0.632 | 36.8% | 36.9% |
| 528 | 0.850 | 15.0% | 15.4% |
| 543（切口） | 0.986 | 1.4% | 3.1%（深色 0.0%） |

其它断言（`scrollY` 取 500 / 700 / 900 / 1100 / 1179 / 1250，深浅两色）：

- 星空可见底边恒等于 `min(vh, heroBottom)`，切口以下 **0 个星点像素**。
- `reduced-motion` 分支 `cut = 0`、`fade = 0`，不裁剪（`.sf` 此时是 `absolute`，
  本来就在 Hero 高度之内）。

**踩过的坑：截图时机。** `--screenshot` 配 `--virtual-time-budget` 会在滚动的 rAF
跑完之前抓图，量到的永远是「还没滚动」的状态（参考线也因此画不出来）。改用 DevTools
协议（`Emulation.setDeviceMetricsOverride` 固定视口 + 等滚动落地再
`Page.captureScreenshot`）才拿到正确结果。

**踩过的坑：墨量阈值。** 亮色下星点是 `rgb(29,29,31)` 以 0.3 alpha 压在近白底上，
合成后约 `#bbb`；按「暗像素」取阈值会得出「一个点都没有」的错误结论。另外半透明
覆盖层合成时底色会取整到 254/255，这个 ±1 的常量偏移会盖过星点本身的信号 ——
所以衰减比只在「硬边图里确实有星点」的那些像素上测。

### 顺带记一处不一致
