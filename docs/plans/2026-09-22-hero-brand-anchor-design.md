# Hero 品牌水印：落点从「图层比例」改成「贴住演示窗壳上沿」

日期：2026-09-22

## 需求

「hero 的 Dithering 效果可不可以加入 DeepStudent 的 icon 的元素，可以往下放一些。」

确认后指的是**已经有**的那个：星空层里另起一张细网屏画布（`.sf__brand`），把
`docs/public/logo-black.svg` 阈值化成网点水印，压在画面左侧。诉求是整体往下沉一些。

## 为什么不能直接改那个 50%

原来是 `BRAND_ANCHOR_Y = 0.5`（占图层高度的比例）。往下调它有两个独立的问题：

1. **会被演示窗壳切出一条直线。** 窗壳是不透明的、左边界在 x=180，而图标右缘在
   x=256 —— 已经伸到那条边右边。图标只要有任何一部分落到窗壳上沿（y=477）之下，
   就被窗壳的左上角切掉一块。所以淡出必须**在触到那条边之前归零**，
   而淡出的终点原本是写死的 `fy = 0.95`，正好等于「图标贴着窗壳上沿」——
   一动落点，这个等式就破了。
2. **视口一变高，图标跟着漂，窗壳不漂。** 图层高 118vh，按比例定位意味着图标纵向
   位置乘上了视口高度；而窗壳是排版撑出来的、只跟宽度走。实测（静止态）：

   | 视口 | 旧落点（图标外接方框顶边 y） | 窗壳上沿 y |
   |---|---|---|
   | 1440×900 | 235 | 477 |
   | 1440×1400 | 440 | 477 |
   | 1440×1800 | 604 | 477 |

   1400 高时图标已经沉进窗壳里，1800 高时整块都在窗壳后面。改完之后三种高度
   都落在 283，淡尽线与窗壳上沿恒定重合。

## 设计

把「落点」和「淡出终点」合并成同一个约束：**窗壳的上沿就是淡尽的那条线。**

- 新增 prop `blocker`（HomePage 传演示窗壳 `.lp-hero__demo`）。它的**上沿**是基准。
- 新增常量 `BRAND_VISIBLE`：图标有多少落在窗壳上沿**之上**（占图标边长）。
  落点由它反推：`中心 = 窗壳上沿 − size × (BRAND_VISIBLE − 0.5)`。
  于是「下沉多少」只剩这一个旋钮，而且换任何视口高度都自动跟着窗壳走。
- 淡出终点从写死的 `0.95` 改成 `BRAND_VISIBLE`，起点 = 终点 − `BRAND_FADE_BAND`。
  归一化坐标下正好等于图标方框坐标，与画布分辨率无关（落点那侧乘的
  `size × scale` 与 `off` 在推导里抵消）。
- `BRAND_VISIBLE = 1` 就是旧行为。取 **0.75**：在 1440×900 上比原来低 **48px**
  （外接方框顶边 235 → 283）。`BRAND_FADE_BAND` 同时从 0.6 收到 **0.4** ——
  起点仍是 `fy = 0.35`，和改之前一样，于是这次的效果就只剩「整体下沉」，
  形状的浓度分布没有被顺手改掉。

顺带修掉两个在实现里撞出来的坑：

- **量到的是入场动画的中间态。** 原来想用 `getBoundingClientRect().top + scrollY` 拿
  文档坐标，但窗壳所在的 `.t-stagger-line--5` 带 `translateY` 入场，而 logo 的 `<img>`
  通常在动画没跑完时就 `onload` 了 —— 实测那一瞬间量到的顶边带着 **12px** 位移，
  图标就被永久按下沉 12px 落位。改成累加 `offsetTop` 链（只反映排版结果，与动画无关）。
- **降级态的图层顶边不在 0。** `prefers-reduced-motion` 下 `.sf` 从 fixed 改成 absolute、
  跟着文档走，顶栏占了 64px 的位，不减掉的话图标正好被窗壳横切一刀。
  现在这段偏移按 `reduced` 分叉：fixed 态减 `--sf-y`（静止态 = Y_START），
  降级态减图层自身的排版顶边。

## 验证

无头 Chrome（CDP）实测，dev server 5174：

| 场景 | 图标上沿 y | 窗壳上沿 y | 结论 |
|---|---|---|---|
| 1440×900 浅色 | 283 | 477 | 淡尽线与窗壳上沿重合 |
| 1440×900 深色 | 283 | 477 | 同上 |
| 1440×1400 浅色 | 283 | 477 | 不再随视口高度漂（旧实现会偏 157px） |
| 1280×800 浅色 | 283 | 477 | 同上（窗壳左边界左移到 100） |
| 1440×900 降低动效 | 283 | 477 | 与常规态一致 |

- `npm test`：14/14 通过。
- `NODE_OPTIONS= npx vitepress build .`：build complete，无新增告警。
- 视口 < 1160px 时仍然不画（`BRAND_SIZE_MIN` 的守卫没动）—— 窄屏上栅格没有余量，
  放哪都会压到文案。

## 已知未做 / 取舍

- **滚动到 Hero 中段时，图标的右侧一小条会滑到窗壳后面。** 淡出是按静止态烘焙进画布的
  （静态层、不进逐帧循环是刻意的），而滚动时窗壳会往上走过图标。这是上一版就有的行为，
  这次没动：位置只差 48px，观感没有变差。要彻底解决得让淡出跟着窗壳实时重算，
  代价是每次滚动都要重跑一遍阈值化。
- **没有更低的档位可选。** `BRAND_VISIBLE` 继续调小就是「实心部分越来越少」，
  0.6 以下基本只剩顶部一条边，形状读不出来。想再低只能缩尺寸塞进窗壳左侧
  那条 180px 的窄栏（`BRAND_SIZE_MIN` 会拦住）。
