# 功能区电脑框架（DeviceFrame）

日期：2026-09-17
状态：已实现（桌面 / 平板 / 手机三档 + 亮暗两套均已核对）

## 背景

功能区的标题是「四件事，装进同一个窗口。」（英文 `Four tools, one window.`），
但原先四个 tab 各配一张独立截图 —— 画面是「四张」，不是一个窗口，
标题和内容说的不是同一件事。这次把四张图收进同一台电脑。

## 已确认决策

| 决策点 | 结论 |
|---|---|
| 机型 | 笔记本（上盖 + 底座）。16:10 屏与四张截图 2400×1500 完全一致 |
| 位置 | 功能区；Hero 的实时演示窗壳（`AppShell.vue`）不动 |
| 屏内内容 | 图片（复用现有四张功能截图） |
| 框的复用性 | 内容走默认插槽，以后换视频只改内容，不改框 |

## 一、框不动，只换屏里的画面

这是这次的核心。

原来的 `.t-panel-slide` 加在整个面板上（文字 + 图一起 `translateY(100px)` + 模糊 + 淡出）。
照搬的话，切 tab 时那台电脑会跟着飞出去再飞回来 —— 正好毁掉「同一个窗口」的意思。

现在拆成两条动线：

- **文字列**：保留 `.t-panel-slide`（位移 + 模糊 + 淡入淡出）
- **屏幕内容**：`.lp-screen` 只做 `opacity` + `scale(1.015 → 1)`

不做位移的原因：屏幕是 `overflow: hidden` 的固定比例盒子，在里面做纵向位移会变成一道
「擦除」动画，比淡入淡出吵得多。

两者共用同一个 `panelOpen` 开关，时序天然同步：淡出 350ms → 换 `src` → 淡入 400ms。

## 二、屏幕锁 16:10

四张截图都是 2400×1500 = 1.6 = 16:10。屏幕用 `aspect-ratio: 16 / 10` 锁死，
`object-fit: cover` 一个像素都裁不到，也避免了「换 tab 时整块高度跳动」。

将来若换非 16:10 的素材：`<DeviceFrame ratio="4 / 3">` 即可，但 `cover` 会开始裁边，
需要重新确认截图内容能不能裁。

## 三、机身：三层结构，上盖与底座等宽

第一版把机身做成「一圈银色边框 + 上盖比底座窄」，实机看不像 MacBook。照着真机的正面观感返工成三层：

```
铝壳外圈（细，clamp 2–3px）→ 黑色玻璃边（clamp 5–9px）→ 屏幕
```

三处关键修正：

| 问题 | 第一版 | 现在 |
|---|---|---|
| 屏幕四周是银色 | 一圈银边包着屏幕，读起来像通用显示器 / 电视 | 屏幕四周是**黑色玻璃**，铝壳只在最外圈留一条细边 —— 这是最露怯的一点 |
| 上盖比底座窄 | 上盖 93% / 底座 100%，是「显示器搁在底座上」 | 两者**等宽**（都 100%）。真机的屏幕总成与底壳就是齐平的 |
| 缺铰链缝 | 上盖和底座直接焊在一起 | 底座上缘一道 2px 暗线（`inset 0 2px 0`，用 inset 阴影而不是伪元素，才能跟着圆角收边） |

等宽顺带解决了第一版的一个隐患：底座宽出 4% 会溢出 `.lp-split` 的栅格列，
窄屏上还会顶出横向滚动条。

另外补了两个真机细节：

- **摄像头刘海**：从屏幕顶边往**屏幕里**垂下来的一块（MacBook Pro 14/16 与 Air M2 之后）。
  注意不能画在边框里 —— 它和边框同色，画进去直接隐形（第一版就踩了这个坑）。
  所以它挂在 `.df__screen` 内部、插槽之后，才能盖在画面上。
- **前缘抠手凹槽**：底座底边居中那道，开盖用的。

圆角是三层递进的：铝壳 16px → 玻璃 13px → 屏幕 `calc(玻璃圆角 - 玻璃边宽)`，
这样边框宽度随视口缩放时圆角不会穿帮。

### 写实层（2026-09-17 追加）

形态对了之后又加了一层质感，写实感靠四处叠出来，全部收在 `--df-*` 变量里：

| 层 | 做法 | 为什么 |
|---|---|---|
| 铝壳 | 底色 + 166° 斜向扫光：顶缘最亮 → 中段转暗 → 底缘回亮 | 金属的「转折」全靠这条明暗曲线，纯色会像一张纸 |
| 玻璃反光 | 104° 斜向淡光 + 边缘一点冷紫偏光 | 真实屏幕的防反射镀膜斜看会泛冷色，这是「玻璃」与「贴纸」的分界 |
| 屏幕内沿 | `inset` 暗角挂在覆盖层上 | 直接写在 `.df__screen` 上会被截图的子元素盖掉（子元素绘制在内阴影之上） |
| 接触阴影 | 紧贴底缘一条硬影 + 两层散开的软影 | 机器才会像「落」在页面上，而不是浮着 |

反光盖在**整块玻璃**上（`.df__glass::after`，边框 + 屏幕一起），不是只盖屏幕 ——
真机上这两者本来就是同一块玻璃，反光扫过去是连续的。
它同时是 `.df__screen` 之后绘制的兄弟元素，但刘海带 `z-index: 1`，仍然压在它上面。

**没做底部倒影**：镜像倒影需要一块「有光泽的地面」才成立，而这个区块的背景是平的；
另外 `-webkit-box-reflect` 绘制在元素盒之外、不占布局，会把倒影糊到下一个区块里去。

### 关于「换成真实 MacBook 素材」

评估过，没有走。Apple 的[第三方商标与版权指南](https://www.apple.com/legal/intellectual-property/guidelinesfor3rdparties.html)
明确写着：

> Apple does not support the use of its logos, company names, product names, or **images of Apple products**
> by other parties in **marketing, promotional or advertising materials**...

唯一的口子（开发者展示兼容性）附加了「必须是真机实拍、**非渲染图**」并需取得书面许可两条硬条件。
第三方「免费 MacBook 样机」素材的许可也普遍不可考。所以机身保持**自绘**：
无授权风险，且矢量、可随主题换色。越往写实做越贴近 Apple 条款里「不得模仿其外观」的边缘，
这一点需要产品侧知情。

## 四、图片预热

四个场景共用一个 `<img>`，切 tab 时才换 `src` —— 没预热的话会先看到一块空屏。

- 首屏：只加载当前那张（`loading="lazy"`），不拖慢首屏
- 挂载后：`requestIdleCallback`（3s 超时兜底；不支持时退回 `setTimeout` 1500ms）
  预热其余三张，共约 1.4MB

没有改成「四张全渲染 + `opacity` 切换」：那会在首屏就把四张全拉下来（1.76MB）。

## 五、暗色下的机身

第一版暗色机身用 `#26262c`，实机看整台机器会糊进页面底色（`#1b1b1f`）。提亮后：

| 变量 | 亮色 | 暗色 |
|---|---|---|
| 上盖 `--df-lid-bg` | `#dcdce1` | `#2c2c33` |
| 底座 `--df-base-bg` | `#e7e7eb` | `#35353d` |

## 六、无障碍

原来 `role="tabpanel"` 挂在滑动面板上，且 tab 与 panel 之间没有任何关联。现在：

- tab 加 `:id="scene-tab-{index}"` + `aria-controls="scene-panel"`
- 面板改为承载两列的 `.lp-split`，加 `id="scene-panel"` + `:aria-labelledby="scene-tab-{activeScene}"`

## 验证

- `npm test`：14/14 通过（含 i18n 结构一致性）。
- 桌面 1440 / 平板 820 / 手机 390 × 亮暗两套逐屏核对，溢出元素 0 个。
- 两个 SFC 用 `@vue/compiler-sfc` 校验通过。
- **`npm run build` 未跑通**：Vite 的 `loadEnv` 必须读仓库根的 `.env` / `.env.local`，
  当前环境对该读取弹审批并超时拦截，与本次改动无关。发布前需自行跑一次并在弹窗放行。

> 核对时的一个坑：macOS 上 headless Chrome 的窗口最小宽度是 500px，
> `--window-size=390` 会被夹到 500，截图却仍按 390 裁 —— 看上去像内容溢出。
> 窄屏核对要把页面套进一个 390px 宽的 iframe，不要直接信 `--window-size`。
>
> 另一个坑：核对用的静态样张要**从 `DeviceFrame.vue` 里抽 `<style scoped>` 块注入**，
> 不要手抄 CSS —— 手抄过一次，组件改了样张没跟上，白核对一轮。
> 样张里别忘了 `--df-ratio`：它是 Vue 的 `:style` 绑上去的，缺了屏幕会塌成 0 高。

## 可调参数

- `DeviceFrame.vue` 顶部变量：`--df-rim`（铝壳边）、`--df-bezel`（玻璃边）、
  `--df-radius-lid` / `--df-radius-glass`、`--df-base-height`；
  质感四层：`--df-lid-sheen`（铝壳扫光）、`--df-glass-sheen`（镀膜反光）、
  `--df-screen-inset`（内沿暗角）、`--df-base-shadow`（接触阴影），亮/暗各一套。
  刘海不想要，删掉模板里那一行 `<span class="df__notch" />` 即可。
- `HomePage.vue`：`warmSceneImages()` 的空闲预热超时（3000ms / 1500ms）。
- `custom.css`：`.lp-screen` 的起始缩放 `scale(1.015)`。

## 后续可做
